1现有求解器可能慢在哪全部为待检验假设，由 A1/A2/A5 实测

成本从哪来

分支定界的总成本 ≈ 节点数 × 每节点 LP 成本。SCIP 的 presolve、cuts、heuristics 已经很强，能压的主要是每节点成本和一部分节点数；剩下的节点数由"每个节点选哪个变量分支"决定——这是一个求解器内部反复做几千次、却只能靠廉价启发式做的决策。

本模型为什么可能产生大树（四条假设）

  • 目标由整数计数主导：α_H = 0.65 压在"达标关键用户数 H_C"上，这是个整数计数。大量结构不同的解拥有相同的 H_C，对偶界在一段区间内长时间不动，B&B 必须靠枚举才能证明最优。
  • 候选点近似对称：部署位置来自规则网格，几何上相近的候选点近乎等价，y_l 之间存在近似对称，搜索树容易在等价分支上反复展开。
  • Big-M 耦合导致分数解：带宽 b_ul 与关联 x_ul、部署 y_l 通过逐边上界 M_ul 耦合，LP 松弛倾向于给出大量分散的分数 x/y，根 LP 与整数最优之间留有较大间隙。
  • 回传容量是全局共享约束：固定网关容量 C_G 把所有用户耦合在一起，局部改进难以在局部证明不可行，剪枝变慢。

为什么"更好的分支"是可能的空位

SCIP 默认走 pseudo-cost / reliability 分支：靠历史统计估计每个候选的收益。问题在于统计的冷启动——搜索树前部（深度 0–8）的分支决定对整棵树影响最大，而此时 pseudo-cost 恰恰几乎没有历史数据。

full strong branching 在每个候选上真解两个 LP，决策质量接近上限，但每节点代价高到无法部署。所以存在一个理论空位：用接近 full strong 的决策质量，付接近 pseudo-cost 的代价。这就是学习方法要占的位置。

这一整节是假设，不是结论。本项目不允许先假定"求解器很慢"再去证明。门 1 检验实例是否真的不平凡（秒解比例 ≤50%）；门 2 检验树前部是否真的有足够决策点；门 3 直接检验空位是否存在——如果连完美专家 full strong 都压不下 20% 的节点数或 LP 迭代数，那么该规模本就不需要 learned branching，正确动作是保留负结果、换研究任务，而不是想办法把题目变难（禁止关 presolve/cuts/heuristics，禁止用松 Big-M 制造搜索树）。

2AI 要替换哪一步scope.md §7 GNN 接口契约

精确定义：一个点，不多不少

GNN 只在 SCIP 的 LP branching callback 中运行，把当前 transformed LP 表示成变量—约束二部图，对合法候选集合 𝓑ₙ = lpcands[0 : npriolpcands] 评分排序，返回一个变量；SCIP 拿着它建分支子节点，此后一切照旧。

被替换的不被替换的
当前节点的分支变量选择（原本由 pseudo-cost / reliability 做） 可行性验证、原始界与对偶界、剪枝、最优性证明、终止判断、presolve、cuts、primal heuristics、分支方向、变量固定、warm start

GNN 不预测解、不删变量、不永久固定、不做无证明剪枝。可行域一字不变，最优性证明依然成立——这正是本研究 auditable and feasible-region-preserving 定位的全部含义。

怎么学

  • 行为克隆：离线用 strong branching 全候选评分作专家标签，候选掩码下的分类交叉熵；并列最佳集合 𝓨ₙ 内均匀分配目标，不随机丢弃并列。
  • 标签只来自 train/validation：根节点必查一次，深度 1–8 按 p=0.05 抽样，每实例 ≤10 个标签，单实例标签时限 120 s；未抽样节点用 pseudo-cost 继续探索。正式 test 与 OOD 不生成任何专家标签。
  • 第一版不用 DAgger、强化学习、在线再训练、分数回归 / learning-to-rank。

怎么用（在线预算与回退）

  • 有预算的树前部调用：深度 ≤8、每实例 ≤64 次调用、单次软延迟 0.5 s、累计开销预算 10 s。任一预算耗尽 → 该实例剩余搜索全部交回固定版本的 SCIP 默认分支。
  • 确定性回退条件：无合法候选、LP 状态不适用、模型/特征加载失败、映射或维度不一致、推理异常、输出含 NaN/∞、输出变量不在候选集合、设备或内存异常。
  • 实例级 circuit breaker：接口不兼容或超过软延迟 → 完成当前分支后本实例不再调用。软阈值不是异步强制取消。
  • 不用 softmax 最大值当"低置信度回退"阈值——未校准的 softmax 不是可靠置信概率。
  • 每次回调重建映射 transformed Variable ↔ LP Column ↔ 图节点，禁止按变量名、原始建模顺序或上次回调的列下标复用。
净收益公式（论文里必须写出来的那一行）：
净收益 = 决策变好省下的搜索时间 − 推理与特征提取的累计开销
所以成立需要两个独立的必要条件：①结构性空间存在（门 3：完美专家至少能压 20%）与 ②开销足够小（门 4：累计 AI 开销 / default 墙钟中位数 ≤10%）。任一不成立，方法在原理上就赢不了——这正是它们被放在训练之前的原因。

3最后怎样判断是否成功pilot_protocol §7 · scope.md §8.4

三层判决，逐层解锁

① 方向成立吗 Pilot-A 七道硬门（训练前，60 个隔离场景） → GO / REVISE / STOP GO 只解锁标签生成与训练 ② 实现可信吗 Pilot-B（训练后彩排，实际入选 checkpoint） → 只查实现、计时与回退，不许据此调参 ③ 效果如何 ID test 120 + 三类 OOD 各 60 → 全部哈希对齐后才可运行

三层的问题不同：①问"这条路值不值得走"，②问"我测的是不是我以为的东西"，③才问"到底快了多少"。把 ③ 的失望情绪带回 ① 或 ② 去改参数，是这个项目最主要的风险。

成功的定义

成功 ≠ GNN 赢。成功 = 在预先冻结、不可事后修改的协议下，得到一个可审计、可复现、方向明确的结论。三种落点都算完成，都可写进论文：
(a) GO + 正向：nPDI 配对 bootstrap 95% 区间不含 0 且方向有利，尾部减速可控 → 主结果。
(b) GO + 中性或负向：如实报告"该问题族上 learned branching 无显著收益"，附机制诊断。
(c) STOP（门 3 失败）：负结果 —— "该规模的此类 MILP 不存在可被更好分支利用的结构性空间"，保留全部日志并重选 AI 任务。

用什么判（口径已冻结，不许漂移）

  • 主指标 nPDI：固定跨度归一化 gap 在 300 s 上的时间平均，跨度 Δ_F = 1.0。SCIP 原生相对 gap 只作诊断——目标值跨 0，相对 gap 不稳定。
  • 声明顺序：① nPDI（全部实例，场景级配对）→ ② 证明最优比例、最终 normalized gap → ③ 共同证明最优实例的配对时间、全部实例的节点与 LP 迭代 → ④ P90/P95 尾部减速、超时变化、回退分布 → ⑤ 模仿准确率（仅诊断，不能代替求解性能）。
  • 统计：配对与 bootstrap 单位都是基础场景，不是分支节点；paired nonparametric bootstrap 10,000 次、95% percentile、种子 20260817；ID 按 small/medium/large 层内重采样再合并；OOD 各家族分开报告。
  • 纳入规则：根节点可解、GNN 从未调用、零 eligible 节点、GNN 净减速的实例全部进入主结果；GNN-eligible 子集只作机制诊断，必须与全体结果并列标明。
  • 诚实口径：300 s 超时不得当作"精确 300 s 求解"，只在双方都证明最优的配对上报精确加速比；win/tie/loss 的时间 tie 容差固定 1%，结果出来后不得改。

四条最容易自欺的线（写在结果之前）

不许挑实例不利实例一律保留，不删
不许放松模型不关 presolve/cuts/heuristics，不用松 Big-M 造树
不许偷看测试集哈希冻结前不可运行；意外访问记为 protocol violation
不许事后调参权重、超参、调用预算、tie 容差在测试前锁定
