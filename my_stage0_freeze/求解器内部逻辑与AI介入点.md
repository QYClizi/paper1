## 第一章 先建立一个正确的整体印象

### 1.1 求解器要解决的根本困难

你的问题里有**整数变量**（比如"这个无人机放不放"只能是 0 或 1）。

如果所有变量都能取小数，问题叫**线性规划（LP）**，有成熟算法（单纯形法、内点法），几毫秒到几秒就能解出**精确最优**。

**整数要求一加进来，问题就变得极难**——因为可行解不再是一个连续的凸区域，而是一堆孤立的点，你没法"沿着梯度滑下去"。

穷举？`n` 个 0/1 变量有 `2^n` 种组合。`n=60` 就是 `10^18`，宇宙年龄都不够。

### 1.2 分支定界的核心思想：一句话

> **别去枚举所有解。去证明"大片区域里不可能有更好的解"，然后整片扔掉。**

怎么证明？靠**松弛（relaxation）**：

1. 把"必须是整数"这条要求**去掉**，解一个普通 LP
2. 因为限制放宽了，LP 的最优值**一定不差于**原问题的最优值
   → 对最大化问题，LP 值是一个**上界**：真答案不可能超过它
3. 如果这个上界**比你手里已有的某个可行解还差**，那这片区域里不可能有更好的东西 → **整片扔掉**

**这就是"界（bound）"的用处，也是"分支定界"里"定界"两个字的来源。**

### 1.3 两个界，两个名字

| 名字 | 别名 | 是什么 | 从哪来 |
|---|---|---|---|
| **对偶界** dual bound | best bound、上界 | 「最好还能好到什么程度」 | 松弛（LP）给的 |
| **原始界** primal bound | incumbent、下界 | 「目前实际拿到手的最好解」 | 找到的可行整数解 |

**gap = 对偶界 − 原始界**（最大化问题）。

- 一开始 gap 巨大（对偶界很乐观，原始界可能还不存在）
- 求解过程 = **对偶界往下压，原始界往上顶**
- **gap = 0 的那一刻，就是"证明了最优"**

> **注意**：这个命名不随最大化/最小化翻转。最小化时对偶界在下、原始界在上，但名字不变。**这就是求解器用"原始/对偶"而不用"上界/下界"的原因。**

## 第二章 三个阶段

SCIP 从读入模型到吐出答案，走三个大阶段。

```
┌─────────────────────────────────────────────────────────┐
│  阶段 A：准备（开跑之前）                                 │
│  ─────────────────────────────────────────────────────  │
│  A1  读入模型 → 建立内部表示                              │
│  A2  Presolve（预处理）：化简模型                         │
│        · 删掉冗余约束、固定能确定的变量                     │
│        · 合并等价变量（aggregation）                       │
│        · 收紧变量上下界                                    │
│        · 探测（probing）：试着令 x=0，看能推出什么          │
│  A3  产出「转换后模型」——注意，它和你写的模型不一样了！      │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  阶段 B：求解（主循环，第三章详解）                        │
│  ─────────────────────────────────────────────────────  │
│  B0  处理根节点（特殊：割平面加得最凶）                     │
│  B1  循环：挑节点 → 传播 → 解 LP → 加割 → 启发式          │
│           → 判剪枝 → 分支                                 │
│  B2  直到待办清单空了，或者撞到时限                        │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│  阶段 C：收尾                                            │
│  C1  把「转换后模型」的解映射回你原来的模型                 │
│  C2  输出最优解、对偶界、gap、统计信息                     │
└─────────────────────────────────────────────────────────┘
```

### 2.1 关于 Presolve，有一件事会坑到你

**Presolve 会改掉你的模型。** 具体地：

- 你写的变量 `x_ul`，可能在转换后模型里**已经被固定**（`FIXED`）
- 可能被**合并**进另一个变量（`AGGREGATED`，比如发现 `x1 = 1 - x2`）
- 可能被**多重合并**（`MULTAGGR`，表示成好几个变量的线性组合）

**后果**：当 GNN 在某个节点上看到"候选变量列表"时，那些变量是**转换后模型**里的变量，不是你原始模型里的变量。你必须能把两边对上号。

> 这就是你的**门 2（候选映射正确性）**存在的原因，也是 `getStatus()` 返回 `FIXED / AGGREGATED / MULTAGGR` 这些状态要检查的原因。
> **不做这个检查，你的 GNN 会给错误的对象打分，而且不报错。**

### 2.2 SCIP 的阶段常量

```python
model.getStage()   # 返回当前阶段
```

关键取值：`PROBLEM`（刚建好）→ `TRANSFORMED` → `PRESOLVING` → `PRESOLVED` → `SOLVING` → `SOLVED`

**为什么你需要知道**：很多 API 只在特定阶段可用。比如 `getLPBranchCands()` 只在 `SOLVING` 阶段、且当前节点 LP 已解完时有意义。**阶段不对时调用，SCIP 会给你垃圾数据或者直接崩。**

## 第三章 主循环：一个节点身上到底发生了什么

这一章是全文的核心。**上一版我只讲了四步，那是简化版。真实的是七步。**

```
      ┌────────────────────────────────────────────┐
      │  待办清单（open nodes）非空？              │
      └───────────────┬────────────────────────────┘
                      │ 是
                      ▼
  ①  ┌──────────────────────────────────────────────────┐
      │ 节点选择 Node Selection                          │
      │ 从清单里挑一个节点来做                            │
      │ 默认策略：混合了深度优先 + 最好优先                │
      │ 【钩子：Nodesel】                                 │
      └───────────────┬──────────────────────────────────┘
                      ▼
  ②  ┌──────────────────────────────────────────────────┐
      │ 域传播 Domain Propagation                        │
      │ 不解 LP，纯逻辑推理收紧变量范围                    │
      │ 例：已知 x1=1，约束 x1+x2≤1 ⟹ 直接推出 x2=0       │
      │ 便宜、常常能白赚，甚至直接判定不可行                │
      │ 【钩子：Prop】                                    │
      └───────────────┬──────────────────────────────────┘
                      ▼
  ③  ┌──────────────────────────────────────────────────┐
      │ 解 LP 松弛 LP Solving                            │
      │ 去掉整数要求，解一个线性规划                       │
      │ 得到：本节点的对偶界 + 一个（通常带小数的）解        │
      │ 【钩子：Relax（少见）】                            │
      └───────────────┬──────────────────────────────────┘
                      ▼
  ④  ┌──────────────────────────────────────────────────┐
      │ 割平面循环 Separation Loop  ★ 会来回转好几遍       │
      │ 找一些「所有整数解都满足、但当前小数解违反」的不等式 │
      │ 加进去 → LP 变紧 → 重解 LP → 再找 → …             │
      │ 目的：不分支就把界压下去                           │
      │ 【钩子：Sepa（生成割）、Cutsel（挑哪些割）】        │
      └───────────────┬──────────────────────────────────┘
                      │  （循环回 ③，直到没新割或收益太小）
                      ▼
  ⑤  ┌──────────────────────────────────────────────────┐
      │ 原始启发式 Primal Heuristics                     │
      │ 快速凑一个可行整数解，把原始界往上顶                │
      │ 例：把小数解四舍五入再修一修；局部搜索              │
      │ 找到更好的解 ⟹ gap 变小 ⟹ 后面能剪掉更多            │
      │ 【钩子：Heur】                                    │
      └───────────────┬──────────────────────────────────┘
                      ▼
  ⑥  ┌──────────────────────────────────────────────────┐
      │ 剪枝判定 Fathoming / Bounding                    │
      │ 三种情况把这个节点「结案」，不再展开：              │
      │   (a) LP 不可行         → 这片区域没有解           │
      │   (b) LP 解恰好全是整数 → 找到可行解，更新原始界     │
      │   (c) LP 界不比原始界好 → 这片不可能更优           │
      │ ★ 注意：这三条全是「可证明的」，不是猜的            │
      │ 【SCIP 不开放这个钩子 —— 见第五章】                │
      └───────────────┬──────────────────────────────────┘
                      │ 三条都不满足 ⟹ 必须分支
                      ▼
  ⑦  ┌──────────────────────────────────────────────────┐
      │ 分支 Branching = 变量选择                        │
      │ 从「取小数值的整数变量」里挑一个 x                 │
      │ 劈成两个子节点：x ≤ ⌊v⌋ 和 x ≥ ⌈v⌉                │
      │ （0/1 变量就是 x=0 和 x=1）                       │
      │ 两个子节点丢回待办清单                             │
      │ 【钩子：Branchrule】★ 这是你要替换的地方           │
      └───────────────┬──────────────────────────────────┘
                      │
                      └──────► 回到 ①
```

### 3.1 逐步的具体例子

设有 `x1, x2, x3 ∈ {0,1}`，最大化 `5x1 + 4x2 + 3x3`，约束 `2x1 + 3x2 + x3 ≤ 4` 且 `x1 + x2 ≤ 1`。

| 步 | 发生了什么 |
|---|---|
| ① | 清单里只有根节点，选它 |
| ② | 传播：暂时推不出什么 |
| ③ | 解 LP（允许小数）→ `x1=1, x2=0, x3=1` … 假设得到 `x1=1, x2=0.33, x3=1`，目标 `9.33` |
| ④ | 找割平面：或许能加一条把 `x2` 的小数值切掉 |
| ⑤ | 启发式：把 `x2` 舍到 0，验一下可行 → 得到可行解 目标 `8`。**原始界 = 8** |
| ⑥ | 判定：LP 值 `9.33` > 原始界 `8`，且解不是全整数 → **不能结案** |
| ⑦ | 分支：`x2 = 0.33` 是小数 → 劈成 `x2=0` 和 `x2=1` 两支 |

下一轮从 ① 重新开始，处理这两个新节点之一。

**gap 此时 = 9.33 − 8 = 1.33。** 随着树往下长，左边压下来、右边顶上去，**碰头即证明最优**。

### 3.2 一个关键认知

**⑦ 分支是"没办法了才做的事"。**

②③④⑤⑥ 全是在**试图不分支就把节点解决掉**。只有当传播推不动、割平面切不动、启发式凑不出、界又剪不掉，才被迫劈开。

**所以：分支次数 = 前面所有手段都失败的次数。** 树的大小直接反映了"这个模型有多难被证明"。

**这也解释了为什么收紧 Big-M 会让 headroom 变小**：模型越紧，③ 的界越好，⑥ 剪得越多，⑦ 被调用得越少，树本来就小 —— 留给"更聪明的分支"的空间自然就少了。

## 第四章 全部 AI 介入点（钩子清单）

SCIP 是插件式架构。**每一类插件就是一个 AI 可以介入的位置。**

| # | 步骤 | SCIP 插件 | PySCIPOpt 基类 | AI 要决定什么 | **会破坏最优性吗** | 文献热度 |
|---|---|---|---|---|---|---|
| ① | 节点选择 | `nodesel` | `Nodesel` | 先做哪个节点 | ❌ 不会（只影响顺序） | 中 |
| ② | 域传播 | `prop` | `Propagator` | 传播多狠 | ❌ 不会（推理是可证的） | 低 |
| ③ | 松弛 | `relax` | `Relax` | 用什么松弛 | ⚠️ 松弛必须有效 | 低 |
| ④a | 割平面生成 | `sepa` | `Sepa` | 生成哪些割 | ⚠️ 割必须有效（不切掉整数解） | 中 |
| ④b | 割平面挑选 | `cutsel` | `Cutsel` | 加哪几条割 | ❌ 不会（都是有效割） | **上升中** |
| ⑤ | 原始启发式 | `heur` | `Heur` | 怎么凑可行解 | ❌ 不会（解要过可行性检查） | **高** |
| ⑥ | **剪枝判定** | **没有这个插件** | — | — | — | — |
| ⑦ | **变量选择** | `branchrule` | **`Branchrule`** | **劈哪个变量** | **❌ 不会** | **最高** |
| — | 定价（列生成） | `pricer` | `Pricer` | 加哪些列 | ⚠️ | 低 |
| — | 参数配置 | （外部） | — | 用哪套参数 | ❌ | 中 |

### 4.1 注意第 ⑥ 行：SCIP 不给你剪枝钩子

**这不是遗漏，是设计。**

剪枝的三个条件（不可行 / 全整数 / 界不够好）**全是可证明的**。SCIP 的架构不允许你插进去说"我觉得这个节点没戏，扔了吧"——因为那会直接破坏最优性保证。

**Lee 等 2020 想学剪枝，所以他们不能用 SCIP。他们自己用 Python + Matlab 写了一个 B&B。**

> **这一点很重要**：**插件架构本身就编码了安全性边界。** 你在 SCIP 的合法钩子上怎么折腾，都丢不了最优解。要丢，得先离开 SCIP。

### 4.2 每个钩子的 PySCIPOpt 代码形状

```python
# ⑦ 变量选择（你要做的）
from pyscipopt import Branchrule, SCIP_RESULT
class 我的分支规则(Branchrule):
    def branchexeclp(self, allowaddcons):
        候选, 取值, 小数, n全, n优先, n隐 = self.model.getLPBranchCands()
        # ... GNN 在这里给 候选[:n优先] 打分 ...
        选中 = 候选[最高分的下标]
        self.model.branchVar(选中)
        return {"result": SCIP_RESULT.BRANCHED}

model.includeBranchrule(我的分支规则(), "gnn", "GNN 分支",
                        priority=536870911, maxdepth=-1, maxbounddist=1.0)
```

```python
# ① 节点选择
from pyscipopt import Nodesel
class 我的节点选择(Nodesel):
    def nodeselect(self):
        return {"selnode": self.model.getBestNode()}
    def nodecomp(self, node1, node2):
        return -1  # node1 优先
```

```python
# ⑤ 原始启发式
from pyscipopt import Heur, SCIP_RESULT
class 我的启发式(Heur):
    def heurexec(self, heurtiming, nodeinfeasible):
        解 = self.model.createSol(self)
        # ... 给每个变量赋值 ...
        接受了 = self.model.trySol(解)
        return {"result": SCIP_RESULT.FOUNDSOL if 接受了 else SCIP_RESULT.DIDNOTFIND}
```

### 4.3 优先级怎么用

`priority=536870911` 是 `2^29 - 1`，SCIP 里的最大优先级。设这么高意味着**你的规则永远优先于内置规则被调用**。

如果你的规则返回 `DIDNOTRUN`，SCIP 会**自动往下找优先级次高的规则**。这就是"失败自动回落到默认规则"的实现方式 —— 也是你论文里"any failure falls back to the default rule"这句话的技术依据。

## 第五章 为什么"学变量选择"安全、"学剪枝"不安全

### 5.1 一句话

> **⑥ 决定"留不留"。⑦ 决定"先后顺序"。**

### 5.2 展开

**⑦ 变量选择**：

- 你挑 `x1` 分支，得到两支：`x1=0` 和 `x1=1`
- 你挑 `x2` 分支，得到两支：`x2=0` 和 `x2=1`
- **无论挑哪个，两支加起来仍然覆盖全部可行解。一个都没漏。**
- 挑得好 → 界压得快 → 树小
- 挑得差 → 界压得慢 → 树大，但**最终答案完全一样**

**所以：变量选择只影响效率，不影响正确性。这是数学事实，不是经验观察。**

**⑥ 剪枝**：

- 你说"这个节点扔了"
- 如果这个节点的子树里恰好装着最优解 → **最优解永远找不到了**
- 而且**你不会知道**——求解器照样会输出一个答案，只是那个答案不是最优

Lee 等 2020 自己在论文里写：

> *"If an optimal node is misclassified as non-optimal and is pruned, the optimal solution cannot be found either."*

他们报告的 optimality gap 是 **2.01% – 14.54%**，就是这么来的。

### 5.3 这个区别在论文里怎么写

> *The learned policy scores only the solver's legal branching candidates at each node. Since branching partitions the feasible region exhaustively regardless of which variable is selected, the feasible region and all optimality certificates are preserved by construction; the policy can affect search efficiency but not correctness.*

**"by construction"（构造上）这三个词很重要** —— 它表示这不是实验验证的，是逻辑上就成立的。审稿人无法要求你做实验证明它。

## 第六章 你的项目 vs Lee 等 2020：钩子层面的定位

```
                    主循环
                      │
    ┌─────────────────┼─────────────────┐
    │                 │                 │
    ▼                 ▼                 ▼
  ① 节点选择       ⑥ 剪枝判定        ⑦ 变量选择
    │                 │                 │
    │            ┌────┴────┐            │
    │            │Lee 2020 │            │  ┌──────────────┐
    │            │ 学这里   │            │  │ 你 & Gasse   │
    │            └─────────┘            └──│ 学这里        │
    │              ⚠️ 会丢最优              │ ✅ 不丢最优   │
    │              需自写 B&B              └──────────────┘
    │                                        用 SCIP 插件即可
```

| | Lee 等 2020 | 你 |
|---|---|---|
| 钩子 | ⑥ 剪枝（SCIP 没有此钩子） | ⑦ 变量选择（`Branchrule`） |
| 因此求解器 | **必须自己写 B&B** | **可以用 SCIP** |
| 他们的变量选择怎么办 | 「选第一个未定变量」——最朴素 | **这就是要优化的对象** |
| 他们的 presolve / 割平面 / 启发式 | **基本没有** | SCIP 全套 |
| 最优性 | 丢，Ogap 2.01%–14.54% | 构造上不丢 |
| 报告的加速 | 2.06× – 22.13× | 待测，**预期低得多** |

### 6.1 那个加速数字的陷阱

**他们的 22× 是相对于一个几乎没有优化的自写 B&B。**
**你的加速是相对于 SCIP 默认（可靠性伪代价 + presolve + 割平面 + 启发式，几十年调优）。**

**两个数字不可比。而且不懂行的审稿人会觉得你不如 2020 年的工作。**

**必须做的应对实验**：跑一个「朴素 B&B（DFS + 选第一个未定变量 + 关掉所有 presolve/割/启发式）」 vs 「SCIP 默认」的对比，量化 SCIP 默认本身领先多少倍。**这一段放进论文，读者才知道两把尺子不一样。**

## 第七章 分支规则本身：从最笨到最强

第 ⑦ 步「挑哪个变量」有很多做法。按由弱到强：

| 规则 | 怎么挑 | 代价 | 树大小 |
|---|---|---|---|
| **Most infeasible** | 挑小数部分最接近 0.5 的 | 几乎为零 | 差（常常还不如随机） |
| **随机 / 选第一个** | 字面意思（Lee 2020 用的） | 零 | 很差 |
| **Pseudocost 伪代价** | 记录历史：过去分这个变量，界平均压了多少 → 用历史估计 | 很低 | 中上 |
| **Strong branching 强分支** | **每个候选都真试一遍**（各解两个 LP），看哪个界压得最多 | **极高** | **最好** |
| **Full strong branching (FSB)** | 强分支，且候选一个不落 | 最高 | **最好，是天花板** |
| **Reliability pseudocost (RPB)** ← **SCIP 默认** | 混合：伪代价历史数据够可靠时用伪代价；不够可靠时临时做几次强分支来"补课" | 中 | 很好 |

### 7.1 伪代价的直觉

「上次我分 `x7` 的时候，向下那支界压了 0.8，向上那支压了 1.2。所以 `x7` 大概是个有用的变量。」

**问题**：新变量没有历史，估不准。**这就是"可靠性"的含义** —— SCIP 会数每个变量被分过几次，次数不够就临时跑几个强分支来积累数据。

### 7.2 强分支的打分公式

对候选变量 `x`，当前 LP 目标值 `z`：

```
向下试：固定 x ≤ ⌊v⌋，解 LP，得到 z_down
向上试：固定 x ≥ ⌈v⌉，解 LP，得到 z_up

增益_down = z_down − z          （SCIP 内部按最小化，所以是这个方向）
增益_up   = z_up   − z

打分 = max(增益_down, ε) × max(增益_up, ε)      ← 乘积打分
```

**为什么用乘积而不是求和**：乘积偏好**两边都有收益**的变量。一个变量如果向下能压很多但向上完全没用，它把树劈得很不平衡，实际效果差。乘积会自动惩罚这种情况。

### 7.3 GNN 要学的到底是什么

**输入**：当前节点的状态，编码成一张**二部图**
- 一边是变量节点（每个变量的特征：类型、目标系数、当前 LP 值、小数部分、界…）
- 另一边是约束节点（每条约束的特征：类型、右端项、松弛量…）
- 边 = "这个变量出现在这条约束里"，边特征 = 系数

**输出**：每个候选变量一个分数

**标签**：FSB 算出来的那个乘积打分（或它的排序）

**损失**：让 GNN 的最高分变量 = FSB 的最高分变量（交叉熵 / 排序损失）

**一句话：GNN 是在学"不用真试，光看图就猜出强分支会选谁"。**

## 第八章 怎么看懂 SCIP 的日志

打开输出：

```python
model.hideOutput(False)      # 或者干脆不调用 hideOutput
```

日志表头（节选最重要的列）：

```
 time | node  | left  |LP iter|LP it/n| mdpt |frac |vars |cons |rows |cuts |  dualbound   | primalbound |  gap
```

| 列 | 含义 | 你该看什么 |
|---|---|---|
| `time` | 已用秒数 | |
| `node` | **已处理的节点数** | **这就是门 3 要比的数** |
| `left` | **待办清单里还剩几个** | 一直涨 = 树在爆炸 |
| `LP iter` | 累计单纯形迭代数 | |
| `mdpt` | 当前最大深度 | 很深 = 在钻牛角尖 |
| `frac` | 当前节点有几个小数变量 | 这就是分支候选数 |
| `cuts` | 加了多少割平面 | |
| `dualbound` | **对偶界（上界）** | 往下压的那条 |
| `primalbound` | **原始界（incumbent）** | 往上顶的那条 |
| `gap` | 两者差距 | **收敛到 0 = 证明最优** |

行首的字符表示这一行是谁触发的：`*` = 找到新的最优解（启发式或整数 LP 解），`R`/`s`/`f` 等 = 具体是哪个启发式。

**练习**：跑一个中等难度的实例，把日志存下来，对着上面的表逐列看一遍。**看懂日志 = 看懂求解器在干什么。**

### 10.1 三个已知的坑（都是实测踩出来的）

1. **强分支增益方向是 `down − lpobj`，不是 `lpobj − down`。** SCIP 内部一律按最小化处理，即使你写 `maximize`。方向写反 → **所有打分都是 0，且不报错** → 静默产生一整批废标签。
2. **方法名是 `v.getStatus()`，不是 `v.getVarStatus()`。** 写错时 SCIP 吐一串 `[branch.c:1625] ERROR` 然后 `SCIP: unspecified error!`，完全看不出真实原因。
3. **候选只取前 `n优先` 个**（`npriolpcands`），不是全部 `n全部`。
