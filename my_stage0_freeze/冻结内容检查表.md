## 1. 模型 `scope.md §2–§5`

- [ ] **问题**：MILP。UAV 部署位置（离散候选网格）+ 用户关联（每用户至多接一架）+ 下行接入带宽分配与固定回传容量下的流量承载。
- [ ] **目标**：最大化 `α_H·H_C − α_Q·Q_C + α_R·R_all − α_D·D_frac`，权重 `0.65 / 0.20 / 0.14 / 0.01`（正、和为 1、严格递减）。**训练 / ID test / OOD 共用同一组权重，禁止在测试集上重新调权。**
- [ ] **用户**：关键用户占 20%（四舍五入后精确）+ 普通用户；关键用户最低速率 2 Mbit/s。
- [ ] **线性性**：全部无线与能量系数在优化前预计算；模型内无两个决策变量相乘。
- [ ] **允许的强化**：仅 v0.2 已批准的等价强化与数值缩放 —— 逐边紧上界 `M_ul`、冗余有效不等式、MHz/Mbit·s⁻¹/kJ 内部缩放（须可无损还原）。加入前后整数可行域与最优值必须一致。
- [ ] **安全删边**：仅在 `M_ul < b_min − 1 Hz` 时删；相等或差 ≤1 Hz 的边保留。
- [ ] **平凡解**：`y=x=b=z=0, δ_u=q_u` 必须可行；计时起点向所有方法提交并验证求解器确实接受。
- [ ] **能量约束**：主 ID/OOD 下静态冗余，只能称"安全可行性约束"，**不得说部署由能量驱动**；须用实测 `d_l^fly` 判定，不得引用文档估算值。
- [ ] **AI 介入点**：GNN 只在 SCIP 允许的候选里挑一个变量。不预测解、不决定分支方向、不删变量、不永久固定、不做无证明剪枝。任何失败/超时/映射不一致一律回退 SCIP 默认分支 ⇒ 可行域一字不变，最优性证明成立。

## 2. 数据划分 `scope.md §9` · `yaml: evaluation_protocol.dataset_split`

- [ ] **划分单位**：基础灾情场景。**禁止节点级随机划分**；必须在任何标准化、标签、缓存生成之前先划分。
- [ ] **ID 划分**：800 个基础场景 → 70/15/15 = train 560 / validation 120 / test 120，固定种子。
- [ ] **规模构成**：small/medium/large — train [168, 224, 168]、validation [36, 48, 36]、test [36, 48, 36]。
      规模定义：small = 30 用户 / 4×4 / ≤3 UAV；medium = 45 / 5×5 / ≤4；large = 60 / 6×6 / ≤5（区域 2000 m 见方）。
- [ ] **Pilot 场景**：60 个（三档各 20），与 train/validation/test/OOD 完全隔离；**禁止按实测求解时间或 GNN 收益筛选**；pilot 标签全部丢弃并加入哈希黑名单。
- [ ] **OOD 三族**（各 60 实例，一次只改一个主因素）：
      `OOD-size` 用户/候选点数超训练范围（2500 m、80 用户、7×7、≤6 UAV）；
      `OOD-structure` 未见聚集强度或几何（30 + 30）；
      `OOD-backhaul` 未见网关锚点族或更紧的回传瓶颈。
- [ ] **泄漏控制**：归一化统计只在 training 场景上拟合并冻结哈希；跨划分重复场景指纹 fail-closed；缓存按 `protocol_id/split/scenario_hash/model_hash/solver_hash` 隔离，跨命名空间复用禁止。
- [ ] **种子分域**：场景生成 / 划分 / 标签抽样 / 训练 / 求解器 / bootstrap 六域独立配置、独立记录，不得从实例编号隐式复用同一随机流。
- [ ] **测试集封锁**：test/OOD 在模型、checkpoint、归一化、调用预算、统计脚本、方法顺序清单全部哈希冻结前不可运行；意外访问 = protocol violation，重建未访问的测试版本。

## 3. 四种比较方法 `scope.md §8.2`

| ☐ | 方法 | 角色与约束 |
|---|---|---|
| ☐ | SCIP 默认分支 | 主基线（未修改）。须先记录该 SCIP 版本的**实际**默认分支配置，避免把同一策略换名当成两个基线 |
| ☐ | 纯 pseudo-cost | 第二基线 |
| ☐ | 全合法候选 GNN | **主方法** |
| ☐ | 部署变量 GNN | 消融：复用同一 checkpoint，只改候选掩码 ⇒ 只能解释为"同一模型的部署候选掩码消融"，**不能说成独立训练的 deployment-only GNN** |
| ☐ | vanilla full strong | 非第五种方法：只在可承受的小中型子集作慢专家参考 |

- [ ] **公平性**：相同构建、数学模型、presolve、cuts、primal heuristics、单线程、随机种子、时限、gap 容差、实例顺序、硬件；只替换分支策略。**禁止关闭或削弱 presolve/cuts/heuristics，禁止用松 Big-M 制造搜索树。**

## 4. 时间限制与计时 `scope.md §8.3` · `pilot_protocol §9.2`

- [ ] **正式时限**：300 s，`gap 容差 = 0`，单线程；SCIP 10.0.2 / PySCIPOpt 6.2，参数文件 `scip_10_0_2_stage0_v0_2.set`（内容哈希须在 Pilot-A 前保存核对）。
- [ ] **超时口径**：**300 s 超时 ≠ 精确 300 s 求解**。超时实例保留 incumbent / dual bound / normalized gap / nPDI；只在双方都证明最优的配对上报精确加速比。
- [ ] **Pilot 时限**：A1 跑到 60 s 存检查点 → A2 在相同配置下**续跑**至 300 s；两个时点的终止状态、bound、节点、gap 成对报告。续跑等价性必须先通过 A0 单元测试。
- [ ] **墙钟定义**：外部单调时钟包住整个 `optimize()`，含特征提取、CPU/GPU 传输、GNN 推理、后处理、回退、低开销日志；同时保存 SCIP 内部 solving time。模型加载与预热允许一次且单独报告。
- [ ] **运行顺序**：预生成并保存到清单的平衡 Latin-square 顺序；**禁止总是先跑 default 或总是最后跑 GNN**。正式计时不并发，每次求解固定单线程。
- [ ] **重复次数**：预跑中 default 外部墙钟 ≤10 s 的场景，四方法各独立跑 3 次取中位数，其余各 1 次；三次不能只重复表现好的或差的方法。
- [ ] **调用预算**：GNN 深度 ≤8、每实例最多 64 次调用、单次软延迟 0.5 s、累计开销预算 10 s；测试前锁定。

## 5. 主要指标与统计 `scope.md §8.4` · `yaml: statistical_protocol`

- [ ] **主指标 nPDI**：固定跨度归一化 gap 在 300 s 上的时间平均。逐分量安全解析范围 `[−0.21, 0.79]`，跨度恰为 `Δ_F = 1.0`。
- [ ] **有效 dual**：SCIP 首次给出有限上界前取解析上界 `α_H + α_R`，之后取 `min(α_H+α_R, SCIP dual)`。权重敏感性用对应 profile 的值，**禁止把 0.79 硬套给其他 profile**。
- [ ] **口径纪律**：SCIP 原生相对 gap 只作诊断字段（目标值跨 0），不得作 PDI 主定义；nPDI 按 incumbent / 有效 dual 更新事件构造的分段常数轨迹积分，不作结果驱动的截断或平滑；无 incumbent 的运行标记**无效**而非静默填零。
- [ ] **声明顺序**：① nPDI（全部实例，场景级配对）→ ② 确认性（证明最优比例、最终 normalized gap）→ ③ 效率（共同证明最优实例的配对时间；全部实例的节点与 LP 迭代）→ ④ 安全（P90/P95 减速、超时变化、调用与回退分布）→ ⑤ 模仿指标（仅诊断，不能代替求解性能）。
- [ ] **推断统计**：配对单位与 bootstrap 单位均为基础场景，不是分支节点；paired nonparametric bootstrap，10,000 次，95% percentile 区间，统计种子 `20260817`；ID 按 small/medium/large 层内重采样再按冻结比例合并（`scipy.stats.bootstrap` 不支持，须自写并做单元测试）；OOD 各家族分别报告。
- [ ] **尾部**：P90/P95 在完整 120 个 ID test 与每个完整 60 实例 OOD 家族上报告；30 实例子组只报 P90、最大值和逐实例散点。
- [ ] **纳入规则**：**根节点可解、GNN 从未调用、零 eligible 节点、GNN 净减速的实例全部进入主结果。** `GNN-eligible` 子集只作机制诊断，必须与全体结果并列标明。
- [ ] **tie 容差**：win/tie/loss 时间 tie 容差固定为相对默认时间的 1%；短任务先取三次中位数再判定，正式结果出来后不得改值。

## 6. Pilot-A 七道硬门 —— 唯一规范定义 `pilot_protocol_v0.2.md §7`

| ☐ | # | 类别 | 门（阈值含边界） | 判定范围 | 失败后果 |
|---|---|---|---|---|---|
| ☐ | 1 | 难度 | `root solved 或总时间 ≤2 s` 的实例比例 **≤ 50%** | medium、large 分别判，两档都须过；分母 = 该档全部 20 个 pilot 实例 | REVISE |
| ☐ | 2 | 机会 | ≥ **50%** 实例在深度 0–8 内有 **≥10 个** GNN-eligible 节点 | medium、large 分别判，两档都须过 | REVISE |
| ☐ | **3** | **headroom** | 逐实例配对降幅的**中位数** `median_j(1 − fullstrong_j/default_j)`，节点数或 LP 迭代数**至少一项 ≥ 20%**（不是"中位节点数之比"） | medium、large 各在"双方均于 300 s 内证明最优"的可比配对上判；每档至少 5 个有效配对，不足即失败 | **可能直接 STOP** |
| ☐ | 4 | 经济性 | shadow inference 每实例"累计 AI 开销 / default 端到端墙钟"比值**中位数 ≤ 10%** | medium、large 分别判；shadow 模型无需训练，测的是调用成本不是准确率 | REVISE / 改 root-only |
| ☐ | 5 | 标签 | 完整**根**标签率 **≥ 80%** | small、medium、large 各自判；每个根节点可分支实例都必须尝试查询，不得按耗时或预期成功率筛选；任一档零分母不能按 `0/0` 通过 | REVISE |
| ☐ | 6 | 信息量 | 同时满足 ①全部关键用户 `z_u=1` ②独立 evaluator 重算 `Q_C ≤ 1e−8` ③共享网关利用率 `ΣS_u/C_G ≥ 0.95` 的实例比例 **≤ 80%** | medium、large 分别判 | REVISE |
| ☐ | 7 | 正确性 | 候选映射**零错误**；教师 parity 身份/顺序精确一致 + `atol=1e-9, rtol=1e-7` **零不一致**；全部故障注入触发预期回退 | 全局；每个实际执行的对比回调都进入分母 | REVISE |

**推荐执行次序**：A0 → A1/A2 → A5-headroom → 判门 1、3、6 → A3 候选映射 → A4 标签路径 → 判门 2、5、7 → A5-shadow → 判门 4 → A6。
理由：门 3 是唯一能判 `STOP` 的门，却最便宜（只需把 `vanillafullstrong` priority 调高、`donotbranch=false`，不需候选映射和 C 层接口）—— 在投入上百小时接口开发之前先拿到"方向是否成立"的答案。

**不得用多个门的平均表现抵消任一 P0 正确性门失败。** A0 的缩放等价与独立复算是前置正确性条件，不另算第八道门。

## 7. 解锁链与红线 `scope.md §10` · `pilot_protocol §1、§8`

```
baseline 实现
   ↓
Pilot-A 七门 → GO
   ↓ 【只解锁】
正式场景 + 标签生成 + 三 seed 训练
   ↓
按最低 validation masked cross-entropy 选 checkpoint（并列取较小 seed，写入 manifest）
   ↓
Pilot-B（必须用实际入选 checkpoint，不得用 seed 0 代替）
   ↓ 【两个 manifest 与全部哈希对齐才解锁】
ID test + 三类 OOD
```

**Pilot-A 判 GO 单独不解锁正式 test/OOD。** Pilot-B 结果不得用来重调模型、生成器或求解预算，也不得重选 checkpoint；60 s 与 300 s 的方法排序反转必须报告，但不是通过门、调参或重选的理由。

失败后**禁止**：

- ✗ 关闭或削弱 SCIP presolve / cuts / heuristics
- ✗ 用更松的 Big-M 制造搜索树
- ✗ 根据 GNN 表现挑实例或挑参数
- ✗ 看过 test/OOD 之后修改生成器
- ✗ 从正式结果删除根节点可解 / GNN 未调用 / GNN 变慢的实例
- ✗ 不留决策记录地反复搜索"刚好让 AI 赢"的分布
- ✗ 把教学式 Python 循环称作 native vanilla full strong（若非 native，须统一改名为 `project-defined Python-side all-candidate strong-branching oracle`）
- ✓ **负结果也要完整保留日志与结论，建立新版本，不删不利实例**
