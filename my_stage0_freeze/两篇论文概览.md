**三个必须记住的点：**

1. **P2 是 P1 的保险。** P2 只需要"MILP 模型 + 能精确求解"，这两样你第一天就有。**门 3 挂了、GNN 训不动、学习方法完全失败——P2 一个字都不用改。**
2. **两篇覆盖两个圈子。** 优化圈认识你是"带真实问题的 ML4CO 人"，通信圈认识你是"能给出最优界的人"。单独在任一圈子里你都不稀缺，横跨两个才稀缺。
3. **共同底座只做一次。** 生成器、模型、单位自检、审计——这些工作量算在 P1 头上，但 P2 白拿。这是这个组合最划算的地方。

## 一、论文一：预注册筛选协议

### 1.1 一句话

> **在花任何训练成本之前，先用一个便宜的事前测试，判断这类问题值不值得上学习分支。我们把这个测试量化、冻结、执行，并报告结果——不管结果是好是坏。**

### 1.2 标题（两个结局各一个）

**GO 版**（门全过，GNN 有提升）
> *A Pre-Registered Protocol for Learning to Branch, with a Case Study on UAV Network Deployment*

**STOP 版**（门 3 挂了）
> *When Does Learning to Branch Not Pay Off? A Pre-Registered Protocol and a Negative Result on UAV Network Deployment*

（"pre-registered"这个词用不用，取决于目标场子。优化圈可能更习惯 "a priori" / "predeclared"。见第四节。）

### 1.3 创新点——分级，别混着写

#### ★ 一等：能单独扛住"这有什么新的"

**① 把 FSB 从"事后基线"改造成"事前决策规则"**

> 术语：**FSB = Full Strong Branching = 完美专家**（每次分支把每个候选都试一遍，选最好的；树最小但最慢）。
> **RPB = Reliability Pseudocost Branching = SCIP 默认规则**（快但糙，是要打败的对手）。
> **GCNN** = 学出来的策略（想要 FSB 的准 + RPB 的快）。

##### ⚠️ 先记住这条边界，否则会被秒拒

**"测 FSB"不是新东西。** Gasse et al. 2019 的结果表里就有 FSB 一行（方法列表：FSB / RPB / XTrees / SVMrank / λ-MART / GCNN），此后基本成为惯例。

**新的是用法，不是量。** 同一个数，四处不同：

| | 文献的常规做法 | 本文 |
|---|---|---|
| 何时测 | 训练**完**了，进结果表 | **训练之前** |
| 测什么 | 主要报**时间**（FSB 总是最慢） | 报**节点数**（天花板） |
| 用途 | 当一个**对手**比较 | 当一个**决策阈值** |
| 停止规则 | 无 | **有：20%，事前冻结** |
| 是否验证过其预测力 | **无人做过** | **本文的核心问题** |

**正确的表述**（写进论文时逐字用）：

> *FSB 已被广泛报告为**事后基线**；据我们所知，它尚未被用作**事前的投资决策工具**，其对实际学习收益的**预测力也从未被检验**。*

**错误的表述**（千万别写）：~~"没有标准方法能事前判断"~~ ——审稿人手边就有 Gasse 的表。

##### 这件事为什么仍然值得做

**关键前提：学习分支不是"全都失败"。** Gasse 2019 的原始结果（求解时间，秒，easy / medium / hard）：

| 问题族 | RPB（默认） | GCNN（学习） | 结果 |
|---|---|---|---|
| Set Covering | 8.98 / 60.07 / 1677 | **6.59 / 42.48 / 1490** | 三连胜 |
| Comb. Auction | 2.74 / 17.41 / 136.17 | **1.85 / 10.29 / 114.16** | 三连胜 |
| Cap. Facility Location | 26.55 / 156.12 / 631.50 | **22.10 / 120.94 / 563.36** | 三连胜 |
| Max Independent Set | **8.77** / **110.99** / 2045.61 | 6.43 / 192.91 / 2024.37 | easy 胜、**medium 惨败**、hard 打平 |

（12 格中 GCNN 约赢 10 格。同时注意 FSB 那一行**时间永远最差**——"树最小但最慢"的实证。）

**失败发生在别处：**

- **换新领域** → [Distributional MIPLIB](https://arxiv.org/abs/2406.06954)（USC，Dilkina 组）在 GISP / OTS / SRPN 三个此前未使用的真实分布上训练，报告 **"the trained policy did not outperform SCIP in any of the 3 distributions"**。且**全文只用 RPB 作基线，没有 FSB，也没有任何事前分析**。
- **换更强的模型** → [arXiv:2512.09355](https://arxiv.org/html/2512.09355v1)（2025-12）的 Subgraph GNN 比默认更慢、树更大，稠密实例爆内存。原话："表达能力的计算代价盖过了决策质量的收益"。
- **甚至同一篇论文的不同规模** → Gasse 自己的 MIS medium，GCNN 比 RPB 慢 74%。

##### 真正的动机（比"都失败了"强得多）

> **学习分支在那四个经典合成族上有效；换到新的、真实的领域上反复失效。而且没人能事前分辨。**

**若"全都失败"，领域早就放弃了，不需要筛选测试。正因为"有时灵有时不灵、且事前分不清"，筛选测试才有价值。**

- 天花板 × 捕获率 < 推理开销 → 不用做了
- 成本：几个 CPU 小时。避免的浪费：上百个 CPU 小时 + 数周人力
- 上述两处失败的代价，都是在标签生成与训练全部做完之后才支付的

#### ★★ 升级版：把它从"一个提议"变成"一个被验证的仪器"

Distributional MIPLIB 的 13 个域**公开可下载**，而门 3 的测量是一个参数、零代码。所以：

> **把 headroom 筛选跑在那 13 个域上，看它的预测和文献里已知的结局对不对得上。**

对照答案是现成的 —— 他们自己已经报告了其中 3 个域的真实结局（全败）。若筛选事前就给出"headroom 不足 → STOP"，**那就是仪器有预测力的直接证据**。

论文于是从「提出一个筛选测试，在 1 个问题上用了它」变成「提出一个筛选测试，**在 13 个已知域上验证了预测力**，再用它筛掉一个新问题族」。

**此时你的域数不是 1，是 14（借 13 + 自有 1）。而且仪器的验证部分不依赖 UAV 上门 3 过不过 —— P1 的成败被解耦了。**

⚠️ **必须预注册的诚实条款**：筛选也可能预测不准（headroom 高但学习方法照样输）。这个可能性要写在跑之前，并如实报告。**即使预测不准也是结论**——"专家 headroom 不足以预测实际收益，还需考虑 X"同样可发表，而且更有意思。

#### ★★★ 零成本的回溯验证（性价比可能是全项目最高的一步）

**既然文献普遍报告 FSB，就能从已有论文里回溯验证这件仪器——不用跑任何实验。**

Gasse 2019 一篇就有 4 族 × 3 规模 = **12 个数据点**，每点同时含 FSB 的表现与 GCNN 的实际收益；加上后续文献可凑到数十点。

**问一句话：FSB 的树缩减，能否预测 GCNN 的实际加速？**

| 结果 | 含义 |
|---|---|
| 能预测 | 仪器获得**零成本的历史验证**，且不依赖你自己任何实验 |
| 不能预测 | **本身就是重要发现**——"整个领域参照错了量" |

**两个方向都是结果。** 工作量：读文献 + 做散点图，约 1–2 周。**建议排在第 1–2 个月，与共同底座并行。**

⚠️ 注意：文献多报告**时间**而非节点数，需回到原论文附录取节点数；取不到的点要如实标注剔除，不得静默丢弃。

**② headroom 是模型的性质，不是问题的性质**

这条可能是最有杀伤力的一条。

松的 Big-M → 松的 LP 界 → 大的搜索树 → **看起来 headroom 很大**。
收紧 Big-M → 紧的 LP 界 → 小的搜索树 → **headroom 缩水**。

**同一个问题，换个写法，测出来的 headroom 完全不同。**

推论直指整个领域：**文献里报告的加速，有多少是"模型写松了"的产物？** 现有工作几乎没人报告自己的 formulation 强度。

你的做法是先诚实强化（edge-specific bounds + 保持整数包不变的有效不等式），再测 headroom。这既是你自己的防线，也是给全领域的一条方法学要求。

**③ 可解释难度的测试床**

现有 benchmark 上门 3 挂了，你只能写"这个分布 headroom 不足"，说不出为什么。

你的问题上你能写：**"因为网关容量上限 `C_G_max = 150` 在约 81 用户后开始生效，实例被这个上限主导，整数结构退化。"**

一个能回答"**headroom 为什么低**"的测试床，比只能回答"headroom 低"的，价值高一个量级——前者能推广成规律，后者只是一个数据点。

**④ 捕获率：headroom 能不能预测实际收益**（仅 GO 时可得）

预声明"根据门的测量，预期净收益 = 捕获率 × headroom − 开销"，跑完对照实际值。给出一个"学习方法实际拿到了天花板的百分之多少"的数。

**这是可迁移到别的问题族的知识**，而且只有预注册设计能干净回答（事后配的因果没人信）。

#### ☆ 二等：单独不够，组合起来是防线

- **预声明规模阶梯**（60 → 100 → 150 用户）——把"一次观测"升级为"一条趋势"
- **静态审计推翻自身设计假设**——预实现审计发现每机能量预算在整个实例族上静态冗余
- **完整 artifact**——生成器 + 强化后的模型 + 门的实现 + 全部日志（**含负结果日志**）

#### ✗ 不是创新点，别当卖点写

| 别写 | 为什么 |
|---|---|
| "我们采用了预注册方法" | 借来的形式。NeurIPS 2020/2021 办过 pre-registration workshop（[PMLR v148](https://proceedings.mlr.press/v148/) / [v181](https://proceedings.mlr.press/v181/)），**2022 年起停办**——ML 圈没立住 |
| "我们把 GNN 分支用在了 UAV 上" | 这是 Gasse 方法的一次应用，不是贡献 |
| "我们冻结并哈希了所有阈值" | 方法论卫生，是**手段**不是**贡献**。放正文，不放摘要第一句 |

> **一句话记住：别把论文卖成"我们预注册了"，卖成"我们量化了什么时候学习方法值得做"。**

### 1.7 相关工作与差异化（写作时直接用）

#### 与 Gasse et al. 2019 的关系（必须写清楚，否则秒拒）

**他们已经报告了 FSB。** 本文不主张"首次测量 FSB"，而主张**首次把它当作事前决策工具并检验其预测力**。差异见 §1.3 创新点 ① 的对照表。

**同时必须承认：学习分支在其四个合成族上是成功的**（12 格中约赢 10 格）。**本文的动机不是"学习分支无效"，而是"其有效性不可事前预判"。**

#### 与 Distributional MIPLIB 的关系

**它是什么**：论文（[arXiv:2406.06954](https://arxiv.org/abs/2406.06954)，Huang/Huang/Ferber/Dilkina，USC）+ 数据集（13 个域）。**至今仍是预印本状态**，项目站点未标注同行评审录用。

**品类不同，不要在同一根轴上比**：

| | 资源论文（他们） | 方法论文（你） |
|---|---|---|
| 靠什么赢 | 覆盖广、标准化、好用、被采用 | 想法新、正确、被验证、能迁移 |
| 域的数量 | **核心指标** | **基本不看** |

参照数字：**Gasse et al. 2019（本线开山之作、引用最多）用 4 个域；2025-12 那篇 Subgraph GNN 也用 4 个域。4 个域是方法论文的行业标准。**

**关键差异（可直接写进相关工作）**：

> 现有多领域工作补齐了**分布多样性**，但（a）不提供事前的可行性诊断——学习是否值得，只能在训练完成后才知道；（b）**「有物理机理 + 可批量生成」这个交集仍然极稀缺**：其 5 个真实域中仅 Optimal Transmission Switching 一个提供生成器，其余 4 个只有固定实例文件；（c）难度按**运行时长**分档（Easy <100s / Medium / Hard / Very Hard / Extremely Hard），这是**症状**而非**机理**——无法回答"为什么这批实例难"。

**同时是机会**：本文的实例族做完后可贡献进该库。

#### 一个应当引用并回应的发现

该文报告：**数据有限时，混合分布训练优于同质分布训练，且对更大实例泛化更好。**

这与 **D049（OOD 结构 → 同质 60）** 的设计相冲突。决策记录中必须写明为何仍选同质（例如："本文目的是隔离单一分布上的 headroom，而非最大化泛化能力"），否则会被审稿人直接引用打击。

### 1.8 面向优化圈的表述规范（措辞级，代价很高）

#### ⚠️ 坑一：绝不要写 "real-world instances"

你的实例是**生成的**，不是从真实灾区采集的。写 "real-world" 会被一句"你的灾区数据哪来的"击穿，且属于"作者把话说过头"——比结果不好严重得多。

**正确写法**：

> *"physically-grounded synthetic instances derived from a calibrated wireless propagation model"*
> 或 *"semi-synthetic instances"*

**你的优势从来不是"用了真实数据"**，而是这两条同时成立：

1. 每个系数可追溯到一个物理量（→ 能诊断"为什么难"）
2. 仍然可批量生成同分布实例（→ 机器学习用得上）

**这个交集在 Distributional MIPLIB 里目前只有 1 个域（OTS）。**

#### ⚠️ 坑二：别让审稿人为你的领域复杂度买单

优化圈**不嫌复杂**——他们自己的真实域（潮流方程、ReLU 编码、水力学）一样重。他们嫌的是**没翻译**。

三个动作，加起来不到一页：

**① MILP 先行。** 第 4 节开头先放一张"一眼看懂"表：变量数 / 二元变量数 / 约束数与约束族 / 根节点 LP gap / presolve 后规模 / 目标跨度。物理进附录。

**② 写死这一句：**

> **所有无线与能量系数在实例生成时预计算为常数；模型中不含任何两个决策变量的乘积，故为纯 MILP。**

等于告诉审稿人"**不懂无线也能审这篇**"。物理全部发生在数据生成阶段，模型结构里没有物理量——因此 MILP 的正确性可独立审计（`units.md` 的单位自检表正是为此）。

**③ 结构归位——最有用的一条：**

| 你的东西 | 优化圈的名字 |
|---|---|
| 无人机选址 `y_l` | facility opening |
| 用户接入 `x_ul` | assignment |
| `x_ul ≤ y_l` | **CFLP 的经典 linking 约束** |
| 回程 / 网关容量 | facility capacity |
| 每机能量预算 | 每设施一条背包约束 |
| 带宽分配 `b_ul` | **额外的连续分配层**（CFLP 没有） |

> *"Structurally, our family generalizes the capacitated facility location problem (CFLP) with an additional continuous allocation layer and knapsack-type side constraints."*

**CFLP 正是 Gasse 四件套之一。** 这一句把"完全陌生"变成"我熟悉的东西 + 两处扩展"。

**④ 双命名**：*"We refer to this family as **UAV-Deploy**; structurally, CFLP with continuous allocation (**CFLP-CA**)."* 通信味的名字留给 P2，优化味的名字用于 P1。

#### 最后：复杂度是资产，不是负担

**一个干净的域不可能有有意思的机理解释。** set covering 上 headroom 低，你只能说"低"——那里面根本没有机理。你能说出"网关上限在 81 用户后开始主导，整数结构退化"，**正是因为模型足够丰富到有机理**。

**砍掉复杂度 = 砍掉你最强的那条创新点。**

## 二、论文二：有界背书的方法评测

### 2.1 一句话

> **通信圈解这类问题用的是局部方法（SCA / BCD / DRL），它们给不出对偶界，所以没人知道离最优有多远。我们用精确求解给出这个距离，并画出"什么工况下它们够用、什么工况下差得远"。**

### 2.2 为什么这是个真问题

通信圈的标准套路：把问题写成非凸 MINLP → 用 SCA（逐次凸逼近）/ BCD（块坐标下降）/ 深度强化学习求解 → 报告"我们的方法收敛了，比对比方法好 X%"。

**问题在于：所有对比方法也都是局部方法。** 整个比较是在一群近似解之间进行的，**没有任何一方知道最优解在哪**。

- 论文 A 比论文 B 好 5%，可能两者都离最优差 40%
- 也可能两者都已经在最优的 1% 内，那 5% 的差距根本是噪声

**这个圈子缺一把尺子。你有。**

### 2.3 创新点

**① 首次给出这一问题类的有界背书评测**

不是"我的方法更好"，而是"**这是最优值，你们的方法在这儿**"。

**② 最优性差距地图**

不是一个数，是一张图：横轴用户数 / 纵轴回程紧张度，格子里填 SCA / BCD / DRL 各自的差距百分比。

**产出的是知识，不是排名**：告诉通信圈**在什么工况下可以放心用快方法，在什么工况下必须上精确求解**。

**③ 可复用的评测夹具**

生成器 + 精确求解器 + 评测脚本打包开源。别人提出新方法可以直接拿去量。**这让你的东西变成基础设施，不是一篇孤立论文。**

### 2.4 最大的技术风险：离散化

**必须正面处理，否则审稿人一击致命。**

- 通信方法解的是**连续**的 MINLP（无人机可以停在任何位置）
- 你的 MILP 把位置**离散化到候选网格**上

所以你的"最优"是**网格上的最优**，是原问题的一个**限制**（restriction）。对最大化问题，它是真最优的一个**下界**。

**这反而是好消息，只要你把话说对：**

> "即使把位置限制在离散网格上，精确求解仍然比 SCA 高出 X%。"

这是一句**强于**"我们比它好 X%"的话——因为你自缚一只手还赢了。

**但你必须做网格加密分析**：网格从粗到细，看最优值怎么收敛。如果加密到某个程度值不再涨，说明离散化损失可控。**如果某个通信方法反过来超过了你的网格最优，那说明你的网格太粗**——这是必须自己先发现、自己先报告的事。

### 2.5 投哪里

**首选：IEEE TVT** —— 比 TWC 现实；TWC 更难、更偏理论分析

**其次：IEEE TWC** —— 如果结果强、导师有把握

**也可考虑：IEEE Transactions on Communications (TCOM)**

**写法提醒**：投通信场子，**别把 MILP / 分支定界 / 对偶界当卖点写**，那边的审稿人不吃这套。卖点要写成"**我们首次量化了现有方法的最优性损失**"——用他们关心的语言说他们关心的事。

### 2.6 为什么它对 P1 的结果免疫

| P1 的结局 | P2 受影响吗 |
|---|---|
| 门 3 通过，GNN 大幅加速 | 不受影响 |
| 门 3 通过，GNN 只有小幅加速 | 不受影响 |
| **门 3 失败，STOP** | **不受影响** |
| GNN 训练完全失败 | 不受影响 |
| 侦察发现接口不可用 | 不受影响 |

P2 只需要两样东西：**MILP 模型**和**能精确求解**。两样你第一天就有（侦察已确认 SCIP 10.0 + PySCIPOpt 6.2.1 可用）。

**这就是"保险"的含义。**

### 2.7 备选 P2（如果 P2 主线遇阻）

**鲁棒 / 随机扩展**：灾后场景里用户位置和需求本身是不确定的。把确定性 MILP 扩成两阶段随机规划或鲁棒优化。

- 优点：通信场子和优化场子都能投；工作量可控
- 缺点：创新点弱一些，做的人多

## 四、需要导师拍板的四件事

**按重要性排序，前两条决定整个方案是否成立。**

### ① 能不能接受负结果论文？

如果不能，**框架 B 整个不成立**，必须回框架 A + 通信场子，同时接受门 3 失败就重做的风险。
**这是唯一一个"答案是否，全盘推翻"的问题。必须先问。**

### ② 毕业要求认不认优化场子？

有的组要求 IEEE Trans 一作。如果是，P1 和 P2 的顺序可能要对调（先做 P2 拿通信期刊，再做 P1）。

### ③ 他的背景能不能支撑优化场子？

如果导师是通信出身，你投 MPC / CPAIOR，他可能不认识审稿人、不熟那边的写作规范、判断不了你写得好不好。**这是真实成本，不是可以忽略的。**
如果答案是"不能"，考虑找一个优化背景的合作者或副导师。

### ④ 规模阶梯的现实性辩护

60 → 100 → 150 用户，为什么这个范围在灾后场景下是合理的？需要一个能写进论文的说法。

**同时提醒他一个坑**：`C_G = clip(β_G × 总需求, 50, 150)` 的 150 上限在**约 81 用户**时开始生效。往上爬规模时你其实在悄悄勒紧网关。
**不处理的话，门 3 挂了你会误诊成"没有 headroom"，真实原因却是你自己把水管掐细了。**
