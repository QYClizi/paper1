# 博士首篇论文路线：以学习材料为主的简明版 v0.2

> 你的基础：学过线性代数，会 Java；Python、混合整数优化、无线通信、机器学习和求解器内部算法需要从项目所需部分开始。  
> 你的论文目标：先证明当前 UAV MILP 正确且确实存在可学习的分支空间，再让 AI 帮助 SCIP 选择分支变量，并检查端到端时间是否真的缩短。  
> 本路线不按周排日程，也不安排与论文无关的练习。全程只有两件事：学习必要知识，以及直接完成 paper。

## 先看这一条总路线

按下面的顺序走：

**读懂 v0.2 验收规则 → Java 转 Python → 补少量数学 → 学 MILP 并强化模型 → 学 UAV 通信模型 → 学 SCIP、做 baseline 和 Pilot-A 的非 AI 部分 → 学 PyTorch/GNN 并完成 shadow inference → Pilot-A 最终 `GO` → 正式标签与训练 → 学实验统计 → Pilot-B → 正式实验和论文成稿。**

这里的 baseline 就是“拿来比较的方法”；Pilot-A 是训练前检查问题难度、教师空间、标签和 AI 经济性的硬门；Pilot-B 是训练后、正式测试前使用实际入选 checkpoint 的完整彩排；label 是昂贵老师告诉模型“这个节点最好选哪个变量”；checkpoint 是训练后保存下来的模型；ID test 是与训练条件相似的测试，OOD test 是故意改变规模、结构或回传条件的测试。

你不需要重新学习完整线性代数，也不需要学习完整高等数学。每读一份材料，都必须马上得到一种论文资产：代码、自动检查、公式说明、文献卡、表格模板或可放入正文的段落。如果一项学习不能服务当前 paper，就先不学。

## 大致需要多久

- 材料阅读、项目实现、实验和初稿合计：约 **1200–1800 个真正有效的小时**。
- 按每天 13 小时科研窗口计算，其中真正高质量工作约 9.5–10.5 小时，现实日历大约 **7–10 个月**。
- 第一个可信的 baseline：通常在累计约 500–700 个有效小时后。
- 第一个可以在线运行的 AI 分支方法：通常在累计约 900–1300 个有效小时后。
- 正式实验和完整初稿：通常在累计约 1200–1800 个有效小时后。

这些只是估算。SCIP 的标签接口如果需要额外开发，时间会增加；不能靠少睡觉跳过技术依赖。`100 CPU h` 只覆盖四种方法全部跑满 300 s 的正式求解上界；当前把求解 CPU 时间和训练墙钟混合列账的可量化资源小时约为 `144 h`，加 20% contingency 后的执行规划包络约为 `172.8 h`。这不是最低消耗，也不是总上限，因为 headroom/shadow、Pilot-B 的 300 s 子集、短任务重复、接口开发、调试与失败重跑尚未完全定界；执行与论文中必须再分别报告求解 CPU h、标签 CPU h、训练 CPU/GPU h 和真实墙钟。

### 唯一主教材与准确章节

材料：[Applied Mathematical Programming，Bradley、Hax、Magnanti](https://web.mit.edu/15.053/www/AMP.htm)。章节编号以下列 MIT 官网 PDF 为准。

#### 1. 建模、LP 与求解器输出

- [第 1 章](https://web.mit.edu/15.053/www/AMP-Chapter-01.pdf)：1.3 **Formulation of Some Examples**；1.4 **A Geometrical Preview** 中的可行域、顶点、不可行与无界；1.5 **A Classification of Mathematical Programming Models** 开头的 LP 一般形式和整数限制。例题只跟读一个。
- [第 2 章](https://web.mit.edu/15.053/www/AMP-Chapter-02.pdf)：章首与 2.1 **Simplex Method—A Preview** 的概念和几何解释。知道 LP 求解器怎样改进可行解即可，跳过 pivot、ratio test、canonical-form 表格和手算。
- [第 5 章](https://web.mit.edu/15.053/www/AMP-Chapter-05.pdf)：5.2 **Stages of Formulation, Solution, and Implementation**；5.3 **The Role of the Computer** 只看输入检查、状态、slack 和 row error。

必须区分：2.2 的 big-M 是为 simplex 人工变量设置目标惩罚，本段不学；9.2 的常数 \(B\) 用于逻辑建模，必须有效且尽量紧；本项目的 \(M_{ul}\) 是由已有约束逐边推出的有效上界。

#### 2. 对偶、界和 gap

- [第 4 章](https://web.mit.edu/15.053/www/AMP-Chapter-04.pdf)：4.1 **A Preview of Duality**、4.2 **Definition of the Dual Problem**；4.4 **The Fundamental Duality Properties** 只读 weak/strong duality 与 optimality 的结论，跳过证明和 4.3。
- 对当前最大化模型，任一整数可行解给原始下界，其中最好的才是 `incumbent`；节点 LP 最优值给节点上界，活跃节点上界的最大值形成全局 `best bound`；已有 incumbent 后二者的距离才形成可解释的 gap。

#### 3. 二进制建模和 branch-and-bound

- [第 9 章](https://web.mit.edu/15.053/www/AMP-Chapter-09.pdf) 章首；9.1 **Some Integer-Programming Models** 只读 warehouse location；9.2 **Formulating Integer Programs** 只读 binary variables、logical constraints 和 fixed costs。
- 读 9.4 的 LP relaxation 与错误舍入；精读 9.5 **Branch-and-Bound** 的 Basic Procedure、Summary 和分支选择说明；9.6 **Branch-and-Bound for Mixed-Integer Programs** 只读开头与示意树。

跳过第 3 章、9.3、9.7 及其后各节、章末习题和手算表格。现代 SCIP 的 presolve、cuts、heuristics、callback 与 branching API 留到第六段查官方文档。

### 边看边完成什么 paper 工作

1. **建立唯一模型契约。** 从当前已同步的 `scope.md` v0.2、D036–D044、`notation.md`、`units.md`、`experiment_space.yaml` 和 A0 协议提取集合、参数、变量、约束、目标、单位、来源和测试。确认 \(S_u\) 是派生量、所有物理系数已预计算、没有两个决策变量相乘，因此模型是 MILP 而不是 MIQP。
2. **按约束族增量搭建同一个最终 MILP。** 依次加入：\(y_l,x_{ul}\) 与部署/单关联；连续 \(b_{ul}\)、\(S_u\)、带宽和需求上限；位置与网关回传；\(z_u,\delta_u\) 及其单向语义；最后加入能量安全约束和唯一的归一化加权目标。目标权重固定为 \((0.65,0.20,0.14,0.01)\)，不是词典序目标，能量也不进入目标。增量步骤只用于调试，不是多种论文方法。
3. **从一开始使用 v0.2 强化。** 按 `notation.md` 记
   
   \[
   M_l^E=\max\left\{0,\frac{E^{\mathrm{use}}-E_l^{\mathrm{fixed}}}{T(p_A/\xi_{\mathrm{PA}})}\right\},\qquad
   M_{ul}=\min\left\{B,\frac{d_u}{\eta_{ul}},\frac{C_l^{\mathrm{bh}}}{\eta_{ul}},\frac{C_G}{\eta_{ul}},M_l^E\right\}.
   \]
   
   实现 \(b_{\min}x_{ul}\le b_{ul}\le M_{ul}x_{ul}\) 和 \(z_u\le\sum_lx_{ul}\)。只在 \(M_{ul}<b_{\min}-1\ \mathrm{Hz}\) 时删边或固定为零并记录原因，相等或差值不超过 1 Hz 时保留。松的统一 \(B\) 上界只留在极小实例等价性测试中；default、pseudo-cost、教师、GNN 和消融必须加载同一个最终强化缩放模型及同一 SCIP 参数文件，只改变分支规则。
4. **完成 A0 的 MILP/缩放侧预检。** 用与真实模型结构相同、系数可手工审计的极小实例，先验证平凡解 \(y=x=b=z=0,\delta=q\)，再枚举全部二进制选择并独立处理剩余连续 LP，核对 SCIP 最优解。语义约束做可行/不可行和删除测试；逐边 \(M_{ul}\) 与冗余有效不等式则检查整数可行域和最优值不变，并确认强化后的 LP 上界不高于未强化模型。项目不冻结“3 用户、2 位置”这一尺寸。
5. **完成双层复算与基础审计。** 场景和预计算保存 SI，模型边界集中转成 MHz、Mbit/s、kJ；比较 slack 前先换回同一单位。求解结果必须转回 SI，由不调用模型构造代码的 evaluator 重算全部约束、四个目标分量和总目标。保存变量/约束/非零元数、LP relaxation objective/bound、incumbent、best bound、终止状态，以及主 `normalized_gap=max(0,dual_bound-incumbent)/1.0`；SCIP relative gap 只作诊断。正式比较时从计时起点向所有方法提交同一平凡 incumbent。
6. **同步写 Mathematical Formulation 初稿。** 定义每个变量和派生量；对每个目标项和语义约束写朴素作用及删除后果；对冗余强化说明它不改变整数可行域、只收紧 LP 松弛；说明 \(z_u,\delta_u\) 的预期语义依赖目标方向。能量约束在本段只实现并记录 slack，物理推导和“静态冗余安全约束”的论文表述放到第五段。
