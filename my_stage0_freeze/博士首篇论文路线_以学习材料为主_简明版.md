# 博士首篇论文路线：以学习材料为主

> 你的基础：学过线性代数，会 Java；Python、混合整数优化、无线通信、机器学习和求解器内部算法从项目所需部分开始。
> 你的论文目标：先证明当前 UAV MILP 正确且确实存在可学习的分支空间，再让 AI 帮 SCIP 选择分支变量，并检查端到端时间是否真的缩短。
> 本路线不按周排日程，也不安排与论文无关的练习。全程只有两件事：学必要的知识，以及直接完成 paper。
>
> 术语（baseline / label / checkpoint / Pilot-A / headroom / nPDI 等）见 `项目总览.md` §九，本文件不重复解释。

## 总路线

**读懂验收规则 → Java 转 Python → 搭工程底座 → 补少量数学 → 学 MILP 并强化模型 → 学 UAV 通信模型 → 补最少量描述统计 → 学 SCIP、做 baseline，先跑 full-strong headroom 判掉最便宜的门 → 再做候选映射与教师接口 spike → 学 PyTorch/GNN 并完成 shadow inference → Pilot-A 最终 `GO` → 正式标签与训练 → 学配对推断统计 → Pilot-B → 正式实验和论文成稿。**

### 为什么先跑 headroom

`pilot_protocol_v0.2.md` 的 A0–A6 是产物编号，不是执行次序。七道门的"成本 × 失败后果"差别极大：

| 门 | 需要先写什么 | 成本 | 失败后果 |
|---|---|---|---|
| 门 1（难度） | default SCIP 跑完 60 个 pilot 场景 | 极低 | `REVISE` |
| **门 3（headroom）** | **把 SCIP 内置 `vanillafullstrong` 的 priority 调高，做 default vs full strong 的配对比较** | **低** | **可能直接 `STOP`** |
| 门 6（目标退化） | 独立 evaluator + 默认求解结果 | 低 | `REVISE` |
| 门 2（eligible 节点） | 一个只数 `npriolpcands` 然后返回 `DIDNOTRUN` 的空分支规则 | 低 | `REVISE` |
| 门 7（映射 + parity） | 完整候选映射 + 教师接口 spike（可能要改 Cython） | 极高 | `REVISE` |
| 门 5（根标签率） | 同上 | 极高 | `REVISE` |
| 门 4（shadow 开销） | 完整图提取 + 最终 GNN 结构 | 高 | `REVISE` 或改 root-only |

**门 3 是七道门里唯一可能直接判 `STOP learned branching` 的门，而它的执行成本几乎最低。** 离线打标签才需要 `donotbranch=true` 那个 C 层接口；headroom 比较要的恰恰是 `donotbranch=false`，让 full strong 正常建枝——这用 SCIP 参数就能做到，不需要 Cython 扩展，也不需要候选映射。

所以执行次序是：

`A0 → A1/A2 → A5-headroom → 判门 1、3、6 → A3 候选映射 → A3/A4 教师接口 → 判门 2、5、7 → 第八段 A5-shadow → 判门 4 → A6 决定`

**收益：把"这个研究方向到底成不成立"的答案，从第六段末尾提前到第六A段的后半。** 如果 full strong 在本 UAV MILP 上压不下 20% 的节点数或 LP 迭代数，你会在投入上百小时接口开发**之前**就知道。

## 大致需要多久

- 材料阅读、项目实现、实验和初稿合计：约 **1250–1900 个真正有效的小时**。
- 按每天 **5–7 个有效小时**、每周 5.5 天计算，现实日历约 **12–18 个月**。
- 第一个可信的 baseline：累计约 500–700 有效小时后。
- 第一个可在线运行的 AI 分支方法：累计约 900–1300 有效小时后。
- 正式实验和完整初稿：累计约 1250–1900 有效小时后。

不要按"每天 13 小时、其中 9.5 小时高质量、日历 7–10 个月"来规划。问题不在体力，在研究诚实性：**当实际进度落后于一个不现实的基准时，最先被牺牲的往往不是休息，而是 Pilot 的严格性**——而这个项目的全部价值恰恰建立在"不为让 AI 获胜而改题"上。宁可把日历写长，也不要给自己制造删掉不利实例的压力。

**第六B段的方差最大**：它取决于 PySCIPOpt 冻结版本是否已包装 native vanilla full strong。这是一个二值事实，该段第一天就要查清并重估（见"零号任务"）。

人工小时和机器小时是两回事。机器预算（正式求解、标签、训练、Pilot/审计）见 `yaml: evaluation_protocol.full_project_compute_budget`。

#### 4. 哈希与规范序列化

网页：[hashlib](https://docs.python.org/3/library/hashlib.html) 与 [json](https://docs.python.org/3/library/json.html)

这里的坑非常具体，任何一个不固定 SHA-256 就不可复现：

- 序列化统一用 `json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)` 再 `.encode("utf-8")`；
- **先把所有 NumPy 标量和数组转成 Python 原生类型再序列化**——这是铁律，`np.float64` 与 `float` 的 `repr` 不保证一致；
- 浮点数先按固定规则规范化，并把这条规则写进一页规范；
- 文件哈希与内容哈希分开：`scenario_hash` 是规范化内容的哈希，不是文件字节的哈希。

## 第四段：写对并验证当前 MILP，再理解求解器为什么要分支

预计投入分两部分：

- **阅读教材：约 45–70 小时。** 目标是看懂建模、LP 松弛、界、分支定界和公式强度，不做章末习题，也不训练手算 simplex。
- **直接完成 paper：约 60–100 小时。** 完成模型契约、缩放 MILP、独立复算器、极小实例验收和 Mathematical Formulation 初稿。

本段合计约 **105–170 小时**。这里只使用普通 SCIP 建模和求解接口；候选回调、transformed variable 映射和 strong-branching 教师接口放在第六B段。

### 主教材与准确章节

材料：[Applied Mathematical Programming，Bradley、Hax、Magnanti](https://web.mit.edu/15.053/www/AMP.htm)。章节编号以 MIT 官网 PDF 为准。

#### 1. 建模、LP 与求解器输出

- [第 1 章](https://web.mit.edu/15.053/www/AMP-Chapter-01.pdf)：1.3 **Formulation of Some Examples**；1.4 **A Geometrical Preview** 中的可行域、顶点、不可行与无界；1.5 **A Classification of Mathematical Programming Models** 开头的 LP 一般形式和整数限制。例题只跟读一个。
- [第 2 章](https://web.mit.edu/15.053/www/AMP-Chapter-02.pdf)：章首与 2.1 **Simplex Method—A Preview** 的概念和几何解释。知道 LP 求解器怎样改进可行解即可，跳过 pivot、ratio test、canonical-form 表格和手算。
- [第 5 章](https://web.mit.edu/15.053/www/AMP-Chapter-05.pdf)：5.2 **Stages of Formulation, Solution, and Implementation**；5.3 **The Role of the Computer** 只看输入检查、状态、slack 和 row error。

必须区分三种"大常数"：2.2 的 big-M 是为 simplex 人工变量设置目标惩罚，本段不学；9.2 的常数 \(B\) 用于逻辑建模，必须有效且尽量紧；本项目的 \(M_{ul}\) 是由已有约束逐边推出的有效上界。

#### 2. 对偶、界和 gap

- [第 4 章](https://web.mit.edu/15.053/www/AMP-Chapter-04.pdf)：4.1 **A Preview of Duality**、4.2 **Definition of the Dual Problem**；4.4 **The Fundamental Duality Properties** 只读 weak/strong duality 与 optimality 的结论，跳过证明和 4.3。
- 对当前最大化模型：任一整数可行解给原始下界，其中最好的才是 `incumbent`；节点 LP 最优值给节点上界，活跃节点上界的最大值形成全局 `best bound`；已有 incumbent 后二者的距离才形成可解释的 gap。

#### 3. 二进制建模和 branch-and-bound

- [第 9 章](https://web.mit.edu/15.053/www/AMP-Chapter-09.pdf) 章首；9.1 **Some Integer-Programming Models** 只读 warehouse location；9.2 **Formulating Integer Programs** 只读 binary variables、logical constraints 和 fixed costs。
- 读 9.4 的 LP relaxation 与错误舍入；精读 9.5 **Branch-and-Bound** 的 Basic Procedure、Summary 和分支选择说明；9.6 **Branch-and-Bound for Mixed-Integer Programs** 只读开头与示意树。

跳过第 3 章、9.3（A Sample Formulation）、9.7（Implicit Enumeration）、9.8（Cutting Planes）及其后各节、章末习题和手算表格。现代 SCIP 的 presolve、cuts、heuristics、callback 与 branching API 留到第六A/六B段查官方文档。

#### 4. 公式强度（formulation strength）

AMP 不讲这一点（讲有效不等式的 9.8 已被跳过），但本项目的核心建模贡献恰恰是它：逐边紧上界 \(M_{ul}\) 和冗余不等式 \(z_u\le\sum_lx_{ul}\)，论文里必须论证**"不改变整数可行域，只收紧 LP 松弛"**。没有这一节，这句关键论断就没有可引文献。

材料（二选一，只读第 1 章讲 formulation 的那几页，5–8 小时）：

- [Wolsey, *Integer Programming*](https://www.wiley.com/en-us/Integer+Programming%2C+2nd+Edition-p-9781119606536) 第 1 章 Formulations；
- 或 [Conforti、Cornuéjols、Zambelli, *Integer Programming*](https://link.springer.com/book/10.1007/978-3-319-11008-0) 第 1 章 Formulations。

只需要拿到三样东西：

1. **整数壳**（integer hull / convex hull of integer points）的定义；
2. 两个公式描述同一整数可行集、但松弛可行域一个包含另一个时，"更强 / 更紧"的规范说法；
3. 一张"松 Big-M vs 紧 Big-M"的二维示意图，作为论文里解释 \(M_{ul}\) 强化的插图。

跳过割平面算法、分离问题、完美公式理论和全部证明。

学完直接产出论文里的这一句规范表述：**"\(M_{ul}\) 与 \(z_u\le\sum_lx_{ul}\) 由原模型已有约束推出，因而不删除任何整数可行点，两个公式具有相同的整数壳；但强化后公式的 LP 松弛可行域是原公式的子集，故其 LP 上界不高于原公式。"** 并用下面第 4 点的极小实例枚举实际验证这句话。

#### 3. Primal-dual integral 的原始定义

材料：Berthold, *Measuring the impact of primal heuristics*, Operations Research Letters 41(6), 2013；配合 SCIP 文档中 primal-dual integral 统计字段的说明。

nPDI 是本项目的**主指标**，而你对它做了两处非标准改造——用固定目标跨度归一化绝对 gap（因为本问题目标跨 0，相对 gap 不可用），以及在 SCIP 给出有限上界前用解析上界兜底。要在论文里说清楚"我改了什么、为什么改"，必须先有原始定义可引。

只读：primal integral 的定义式、它为什么衡量整个求解过程而不只是终点、以及它对目标平移/缩放的敏感性讨论。跳过 primal heuristics 的具体算法评估。

#### 4. 实现时查阅

- [SciPy bootstrap](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)：**只借它理解 paired 重采样的语义，以及 percentile 与 BCa 区间的差别。**

  它**不支持** `scope.md` §8.4 要求的"ID 按 small/medium/large 分层，先在层内重采样，再按冻结比例合并"。这个分层配对重采样必须自己写循环实现，重采样次数与统计种子从 `yaml: evaluation_protocol.statistical_protocol` 读。写完后用一个合成数据集做单元测试：构造两组已知中位差的配对数据，验证区间覆盖率符合预期。**不要假设调一个库函数就完事。**
- [Benchmarking in Optimization: Best Practice and Open Issues](https://arxiv.org/abs/2007.03488)：只读问题集、指标、实验设计、展示和可复现部分。其中实验设计部分正好覆盖平衡顺序（counterbalancing / Latin square），可作为方法顺序清单的引用来源。

- **什么时候能第一次知道这个方向成不成立？** 第六A段跑完 A5-headroom、判完门 3 的时候。这一步只需要打开 SCIP 内置的 `vanillafullstrong` 分支规则，不需要 Cython 扩展，也不需要候选映射——所以它必须排在教师接口 spike 之前。
- **什么时候可以开始搭 GNN 结构？** baseline、候选映射、教师接口和 Pilot-A 的非 AI 部分通过以后；这时只能做结构与 shadow inference，不能生成正式标签。
- **什么时候可以生成正式标签并训练？** shadow inference 也通过、Pilot-A 的机器可读决定为 `GO` 以后。
- **什么时候可以做非正式在线实验？** GNN 已接入 SCIP、异常可以安全回退、所有额外时间都能分项记录之后。
- **什么时候可以做正式实验？** 实际入选 checkpoint 已完成 Pilot-B，且模型、数据、参数、指标、运行顺序和分析代码全部冻结以后。
