1模型scope.md §2–§5 · experiment_space.yaml

☐问题MILP：UAV 部署位置（离散候选网格）＋ 用户关联（每用户至多接一架）＋ 下行接入带宽分配与固定回传容量下的流量承载
☐目标最大化 α_H·H_C − α_Q·Q_C + α_R·R_all − α_D·D_frac，权重 0.65 / 0.20 / 0.14 / 0.01（正、和为 1、严格递减）。训练 / ID test / OOD 共用同一组权重，禁止在测试集上重新调权。
☐用户关键用户占 20%（四舍五入后精确）＋普通用户；关键用户最低速率 2 Mbit/s
☐线性性全部无线与能量系数优化前预计算；模型内无两个决策变量相乘
☐允许的强化仅 v0.2 已批准的等价强化与数值缩放：逐边紧上界 M_ul、冗余有效不等式、MHz/Mbit·s⁻¹/kJ 内部缩放（须可无损还原）。加入前后整数可行域与最优值必须一致
☐安全删边仅在 M_ul < b_min − 1 Hz 时删；相等或差 ≤1 Hz 的边保留
☐平凡解y=x=b=z=0, δ_u=q_u 必须可行，计时起点向所有方法提交并验证求解器确实接受
☐能量约束主 ID/OOD 下静态冗余，只能称"安全可行性约束"，不得说部署由能量驱动；须用实测 d_l^fly 判定，不得引用文档估算值
☐AI 介入点GNN 只在 SCIP 允许的候选里挑一个变量。不预测解、不决定分支方向、不删变量、不永久固定、不做无证明剪枝。任何失败 / 超时 / 映射不一致一律回退 SCIP 默认分支 ⇒ 可行域一字不变，最优性证明成立

☐泄漏控制归一化统计只在 training 场景上拟合并冻结哈希；跨划分重复场景指纹 fail-closed；缓存按 protocol_id/split/scenario_hash/model_hash/solver_hash 隔离，跨命名空间复用禁止

☐测试集封锁test/OOD 在模型、checkpoint、归一化、调用预算、统计脚本、方法顺序清单全部哈希冻结前不可运行；意外访问 = protocol violation，重建未访问的测试版本

4时间限制与计时scope.md §8.3 · pilot_protocol §9.2

☐正式时限300 s，gap 容差 = 0，单线程，SCIP 10.0.2 / PySCIPOpt 6.2，参数文件 scip_10_0_2_stage0_v0_2.set（内容哈希须在 Pilot-A 前保存核对）
☐超时口径300 s 超时 ≠ "精确 300 s 求解"。超时实例保留其 incumbent / dual bound / normalized gap / nPDI；只在双方都证明最优的配对上报精确加速比
☐Pilot 时限A1 全部 pilot 场景跑到 60 s 存检查点 → A2 在相同配置下续跑至 300 s；60 s 与 300 s 的终止状态、bound、节点、gap 成对报告。续跑等价性必须先通过 A0 单元测试
☐墙钟定义外部单调时钟包住整个 optimize()，必须含特征提取、CPU/GPU 传输、GNN 推理、后处理、回退、低开销日志；同时保存 SCIP 内部 solving time。模型加载与预热允许一次且单独报告
☐运行顺序预生成并保存到清单的平衡 Latin-square 顺序；禁止总是先跑 default 或总是最后跑 GNN。正式计时任务不并发，每次求解固定单线程
☐重复次数预跑中 default 外部墙钟 ≤10 s 的场景：四方法各独立跑 3 次取中位数；其余各 1 次。三次不能只重复表现好的或差的方法
☐调用预算GNN 深度 ≤8、每实例最多 64 次调用、单次软延迟 0.5 s、累计开销预算 10 s；测试前锁定

5主要指标与统计scope.md §8.4 · notation.md · yaml: statistical_protocol

☐主指标nPDI：固定跨度归一化 gap 在 300 s 上的时间平均。逐分量安全解析范围 [−0.21, 0.79]，跨度恰为 Δ_F = 1.0
☐有效 dualSCIP 首次给出有限上界前取解析上界 α_H + α_R，之后取 min(α_H+α_R, SCIP dual)。权重敏感性用对应 profile 的值，禁止把 0.79 硬套给其他 profile
☐口径纪律SCIP 原生相对 gap 只作诊断字段（目标值跨 0，相对 gap 不稳定），不得作 PDI 主定义。nPDI 按 incumbent / 有效 dual 更新事件构造的分段常数轨迹积分，不作结果驱动的截断或平滑。无 incumbent 的运行标记无效而不是静默填零
☐声明顺序① nPDI（全部实例，场景级配对）→ ② 确认性：证明最优比例、最终 normalized gap → ③ 效率：共同证明最优实例的配对时间、全部实例的节点与 LP 迭代 → ④ 安全：P90/P95 减速、超时变化、调用与回退分布 → ⑤ 模仿指标（仅诊断，不能代替求解性能）
☐推断统计配对单位与 bootstrap 单位均为基础场景，不是分支节点；paired nonparametric bootstrap，10,000 次，95% percentile 区间，统计种子 20260817；ID 按 small/medium/large 层内重采样再按冻结比例合并（scipy.stats.bootstrap 不支持，须自写）；OOD 各家族分别报告
☐尾部P90/P95 在完整 120 个 ID test 与每个完整 60 实例 OOD 家族上报告；30 实例子组只报 P90、最大值和逐实例散点
☐纳入规则根节点可解、GNN 从未调用、零 eligible 节点、GNN 净减速的实例全部进入主结果。GNN-eligible 子集只作机制诊断，必须与全体结果并列标明
☐tie 容差win/tie/loss 时间 tie 容差固定为相对默认时间的 1%；短任务先取三次中位数再判定，正式结果出来后不得改值

7解锁链与红线scope.md §10 · pilot_protocol §1、§8

baseline 实现 ↓ Pilot-A 七门 → GO ↓ 【只解锁】 正式场景 + 标签生成 + 三 seed 训练 ↓ 按最低 validation masked CE 选 checkpoint （并列取较小 seed，写入 manifest） ↓ Pilot-B（必须用实际入选 checkpoint） ↓ 【两个 manifest 与哈希全部对齐才解锁】 ID test + 三类 OOD
Pilot-A 判 GO 单独不解锁正式 test/OOD。Pilot-B 结果不得用来重调模型、生成器或求解预算，也不得重选 checkpoint；60 s 与 300 s 的方法排序反转必须报告，但不是通过门或调参的理由。
失败后禁止的动作
✗关闭或削弱 presolve / cuts / heuristics
✗用更松的 Big-M 制造搜索树
✗根据 GNN 表现挑实例或挑参数
✗看过 test/OOD 之后修改生成器
✗从正式结果删除根节点可解 / GNN 未调用 / GNN 变慢的实例
✗不留决策记录地反复搜索"刚好让 AI 赢"的分布
✗把教学式 Python 循环称作 native vanilla full strong
若非 native，须统一改名为 project-defined Python-side all-candidate strong-branching oracle
✓负结果也要完整保留日志与结论，建立新版本，不删不利实例
