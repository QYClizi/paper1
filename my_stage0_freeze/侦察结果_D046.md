# D046 侦察结果：full strong branching 在 PySCIPOpt 里到底能不能调

> 侦察日：2026-08-19
> 侦察对象：PySCIPOpt master，commit `b5acea9`（2026-08-10）；实测环境 PySCIPOpt 6.2.1 + SCIP 10.0
> 侦察方式：clone 源码逐文件 grep + 装包实跑验证
> **结论：不是 40 小时，也不是 200 小时。是中间那档，而且不用碰 Cython。**

---

## 一、先说什么是"侦察 scip.pxd"

SCIP 是 C 语言写的。PySCIPOpt 是套在它外面的 Python 壳。
**C 里有的函数，不等于 Python 里能调。** 中间要有人手工"接线"，分两步：

| 文件 | 作用 | 类比 |
|---|---|---|
| `scip.pxd` | **声明**：告诉 Cython"C 那边有个函数叫这个名，参数长这样" | 把电线从墙里拉出来 |
| `scip.pxi` / `scip.pyx` | **封装**：真写一个 Python 能调的方法去转发 | 在电线头上装个插座 |

（`.pxd` / `.pyx` / `.pxi` 是 **Cython** 文件。Cython 是介于 Python 和 C 之间的语言，专门用来给 C 库做 Python 接口。）

所以有三种世界：

- 墙里有线 + 有插座 → 直接用，**40 小时**
- 墙里有线 + 没插座 → 自己装插座（写几十行 Cython + 重编译），**80 小时**
- 墙里连线都没有 → 自己拉线再装插座，**200 小时，且必须学 Cython**

"侦察"就是**在写任何代码之前，先花两小时查明自己在哪个世界**。

## 三、最重要的一条：门 3 根本不需要写代码

原来的计划是"自己实现 full strong branching 来测 headroom"。**不用。**
SCIP 自带 `fullstrong` 分支规则，一个参数就能开：

```python
model.setParam("branching/fullstrong/priority", 536870911)
```

实测（40 变量背包类实例，presolve/heuristics/separating 全关，3 个种子）：

| 种子 | default 节点数 | fullstrong 节点数 | 配对降幅 |
|---|---|---|---|
| 0 | 181 | 58 | 68.0% |
| 1 | 71 | 37 | 47.9% |
| 2 | 163 | 104 | 36.2% |

逐实例配对降幅的中位数 = **47.9%**（门 3 的阈值是 20%）

这三行就是门 3 的全部测量机器。**在你自己的实例上跑一遍，就知道有没有 headroom。**

> 注意：这只是随手造的背包实例，用来验证机器能转，**不代表你的 UAV 实例会是什么数**。

## 四、`getVarStrongbranch` 实测可用（这是标签生成要用的）

在自定义 `Branchrule` 里调用，实测输出：

```
根节点 LP 目标值 = -400.6663，合法分支候选 4 个
变量          down增益      up增益        乘积打分  状态
t_x6        0.5378    5.4947      2.9549  COLUMN
t_x8        1.9097    5.8761     11.2214  COLUMN
t_x12       0.1088    3.9577      0.4305  COLUMN
t_x28       6.4220    3.9899     25.6233  COLUMN
→ 专家会选: t_x28
```

可用代码骨架：

```python
from pyscipopt import Model, Branchrule, SCIP_RESULT

class Probe(Branchrule):
    def branchexeclp(self, allowaddcons):
        cands, sols, fracs, ncands, nprio, nimpl = self.model.getLPBranchCands()
        lpobj = self.model.getLPObjVal()
        self.model.startStrongbranch()
        scores = []
        for v in cands[:nprio]:
            down, up, dvalid, uvalid, dinf, uinf, dconf, uconf, lperr = \
                self.model.getVarStrongbranch(v, itlim=-1, idempotent=True)
            dg = max(down - lpobj, 0.0)      # ← 注意方向
            ug = max(up   - lpobj, 0.0)
            scores.append((v.name, max(dg,1e-6) * max(ug,1e-6)))
        self.model.endStrongbranch()
        return {"result": SCIP_RESULT.DIDNOTRUN}

m.includeBranchrule(Probe(), "probe", "probe",
                    priority=536870911, maxdepth=-1, maxbounddist=1.0)
```

### 四个踩过的坑（都是实测踩出来的，不是推测）

1. **增益方向是 `down − lpobj`，不是 `lpobj − down`。**
   SCIP 内部一律按最小化处理，即使你写的是 `maximize`。上面例子里 `getLPObjVal()` 返回 −400.67 是内部值。方向写反的话所有打分都是 0，而且不报错——**会静默产生一整批全零标签**。
2. **方法名是 `v.getStatus()`，不是 `v.getVarStatus()`。**
   写错时 SCIP 会抛出一串 `[branch.c:1625] ERROR` 然后 `SCIP: unspecified error!`，看不出真实原因。
3. **`idempotent=True` 与 SCIP 内建 `fullstrong` 规则不等价。**
   `idempotent=True` 保证调用后求解器状态不变（测量不扰动搜索），代价是丢掉强分支本该产生的定界收缩。所以**你自己实现的 full strong ≠ SCIP 内建 fullstrong 的树大小**。
   → **门 3 用内建参数（第三节），标签生成用这个 API（第四节）。两者不要混。**
4. **候选只能取前 `nprio` 个**（`npriolpcands`），不是全部 `ncands`。

## 五、对排期的影响

| 项 | 侦察前假设 | 侦察后 |
|---|---|---|
| 第六B段工时 | 40 / 80 / 200 小时，未知 | **约 80 小时** |
| 是否要学 Cython | 可能要 | **不要** |
| 是否要重编译 PySCIPOpt | 可能要 | **不要** |
