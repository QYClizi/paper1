## 一句话

**在灾后 UAV 应急通信的部署优化问题上，训练一个图神经网络来替 SCIP 挑选分支变量，并诚实地检验它到底有没有让端到端求解变快。**

关键限定词是"诚实地"。这个项目的全部设计重心不在于让 AI 赢，而在于**建立一条即使 AI 输了也仍然可发表、可复现的证据链**。

---

## 一、研究问题

灾后地面接入基础设施失效，区域内用户只能靠 UAV 基站接入。在 UAV 数量、链路容量、回传容量和电池能量的硬约束下，联合优化三件事：

1. **UAV 部署位置**（从离散候选网格中选）
2. **用户关联**（每个用户至多接一架 UAV）
3. **下行接入带宽分配**，以及固定回传容量下的业务流量承载

用户分两类：**关键用户**（消防、搜救、医护、应急指挥的任务终端，占 20%）和**普通用户**。目标按权重排序为：最大化达标关键用户数 → 最小化关键用户服务缺口 → 最大化全体有效服务量 → 小惩罚少用 UAV。

这是一个 **MILP**（混合整数线性规划）。所有无线和能量系数都在优化前预计算好，模型里没有两个决策变量相乘。

## 二、方法：AI 做什么，不做什么

```
        ┌─────────────────────── SCIP 求解器 ───────────────────────┐
        │  presolve → cuts → 分支定界                                │
        │                        │                                  │
        │              在每个 LP 分支节点：                          │
        │              SCIP 给出合法候选变量集合                     │
        │                        ↓                                  │
        │                  ┌──── GNN ────┐  ← 唯一的 AI 介入点       │
        │                  │ 评分 + 排序 │                           │
        │                  └──────┬──────┘                           │
        │                        ↓                                  │
        │              SCIP 拿着选中的变量建子节点                   │
        │              界、剪枝、可行性、最优性证明 全部由 SCIP 负责 │
        └───────────────────────────────────────────────────────────┘
```

**GNN 只做一件事：在 SCIP 允许的候选里挑一个变量。** 它不预测解、不决定分支方向、不删变量、不永久固定、不做无证明的剪枝。任何失败、超时、映射不一致都直接回退到 SCIP 默认分支。

**因此可行域一字不变，最优性证明依然成立。** 这是本研究的定位 —— `auditable and feasible-region-preserving learning-augmented branch-and-bound`。

**训练方式**：行为克隆。用昂贵的 strong branching 作离线专家，在训练/验证场景的采样节点上生成标签，GNN 学着模仿专家的选择。测试集和 OOD 集**不生成任何专家标签**。

**对比的四种方法**（同一模型、同一参数文件、同一硬件，只换分支策略）：

| 方法 | 角色 |
|---|---|
| SCIP 默认分支 | 主基线 |
| 纯 pseudo-cost | 第二基线 |
| 全合法候选 GNN | **主方法** |
| 只评分部署变量的 GNN | 消融（复用同一 checkpoint，只改掩码） |

另有 vanilla full strong 作为小中型子集上的慢专家参考。

## 三、当前状态与下一步

**状态**：规范全部冻结，代码尚未开始。授权范围是"实现 baseline 并通过 Pilot-A"。

```
✅ 已完成   Stage 0 规范冻结（模型、参数、协议、指标、统计全部定死）
🔨 进行中   实现：生成器 + 强化缩放 MILP + 默认 SCIP baseline + A0 前置检查
⬜ 下一关   Pilot-A 七道 stop/go 门  ← 项目成败的第一个真正判决点
⬜ 被锁定   正式标签生成、GNN 训练           （需 Pilot-A = GO）
⬜ 被锁定   Pilot-B 彩排                     （需 checkpoint 冻结）
⬜ 被锁定   ID test + 三类 OOD 正式实验      （需 Pilot-B 通过且哈希对齐）
```

**解锁链是硬的**：Pilot-A 判 `GO` 只解锁标签和训练，**不解锁正式测试**；正式测试还要等 Pilot-B 通过并核对全部冻结哈希。

## 四、Pilot-A 的七道门（项目的核心机制）

Pilot-A 用 60 个与正式数据完全隔离的场景，在训练之前回答一个问题：**这个研究方向到底成不成立？**

| # | 门 | 通俗说法 | 失败后果 |
|---|---|---|---|
| 1 | 难度 | 问题不能太容易（秒解比例 ≤50%） | REVISE |
| 2 | 机会 | 树的前部要有足够多可供 GNN 决策的节点 | REVISE |
| **3** | **headroom** | **完美专家（full strong）至少能把节点数或 LP 迭代压下 20%** | **可能直接 STOP** |
| 4 | 经济性 | GNN 的推理开销 ≤ default 求解时间的 10% | REVISE / 改 root-only |
| 5 | 标签 | 根节点完整标签率 ≥80% | REVISE |
| 6 | 信息量 | 目标不能退化（不能大多数实例都轻松全达标） | REVISE |
| 7 | 正确性 | 候选映射零错误 + 教师 parity 零不一致 | REVISE |

**门 3 是最重要的一道**：如果连"完美的分支选择"都省不下 20% 的搜索树，那么再好的 GNN 也没有可赢的空间——这时正确的动作是**保留负结果、宣布"该规模无需 learned branching"、换研究任务**，而不是想办法让题目变难。

**门 3 也是最便宜的一道**：它只需要把 SCIP 内置的 `vanillafullstrong` 分支规则 priority 调高，不需要写候选映射，也不需要做 C 层教师接口开发。所以执行次序被特意安排成"先跑门 3"——在投入上百小时接口开发**之前**就拿到方向是否成立的答案。

阈值和判定规则的唯一规范定义在 `pilot_protocol_v0.2.md` §7。

## 五、这个项目最容易被自己骗的地方（防作弊纪律）

整套文档里反复出现的约束，本质上都在防同一件事：**在结果不好看的时候悄悄改题目**。列在这里方便随时自查。

| 纪律 | 具体内容 |
|---|---|
| **不许放松模型** | 禁止关闭 presolve/cuts/heuristics；禁止保留松的 Big-M 来给学习方法制造搜索树 |
| **不许挑实例** | 根节点可解、GNN 从未调用、GNN 净减速的实例**全部**进入主结果 |
| **不许偷看测试集** | test/OOD 在全部哈希冻结前不可运行；意外访问记为 protocol violation 并重建测试版本 |
| **不许事后调参** | 权重、超参数、调用预算、tie 容差在测试前锁定；Pilot-B 结果不能改 checkpoint |
| **不许换 checkpoint** | Pilot-B 与正式测试必须用同一 manifest checkpoint，不能默认用 seed 0 |
| **不许口径漂移** | 主指标是固定跨度 nPDI；SCIP 原生相对 gap 只作诊断（目标值跨 0，相对 gap 不稳定） |
| **不许夸大命名** | 教师若不是 native 实现，必须改名为 `project-defined Python-side ... oracle` |
| **不许夸大结论** | 能量约束在主数据中静态冗余，只能称"安全可行性约束"，不得说部署由能量驱动 |
| **不许伪装超时** | 300 s 超时不能当成"精确 300 s 求解"；只在双方都解出时报精确加速比 |
| **负结果也要发** | 任何门失败都完整保留日志和结论，建立新版本，不删不利实例 |

## 六、已经发现并写进文档的三个"审计成果"

这些是实现前静态审计推翻原始设想的地方，本身就是论文里可以正面报告的内容：

1. **能量约束是静态冗余的**。原设计以为"最远候选接近能量边界所以约束有作用"；静态上界计算证明满带宽下能量约束开始绑定的距离（约 2982 m）严格大于全部候选的最大飞行距离。表述随之降级为"任务安全可行性约束"。（D036）
2. **SCIP 的"全部合法候选"是有歧义的**。精确定义收紧为 `getLPBranchCands()` 返回序列的前 `npriolpcands` 个；同时取消了"原始变量与 LP 列一一对应"的错误假设——presolve 会固定/聚合/删除变量，cuts 会改行集。（D038）
3. **相对 gap 不能驱动 PDI**。目标函数值跨越 0，相对 gap 不是稳定量；改用固定跨度 \(\Delta_F=1.0\) 归一化的绝对 bound gap，并在计时起点向所有方法注入同一个平凡可行解使 incumbent 从头有定义。（D041）

## 七、最大的三个风险

| 风险 | 说明 | 已有的应对 |
|---|---|---|
| **门 3 失败** | 问题规模太小，完美专家也压不下 20% 搜索树 | 提前执行门 3；失败即保留负结果换任务，不硬顶 |
| **教师接口做不出来** | native vanilla full strong 是 C 层函数，PySCIPOpt 未必有包装，可能要改 Cython 重编译 | 第六B段设 80 小时时间盒；到点切 Python-side oracle 并改名 |
| **时间失控** | 接口开发的工时方差极大（40–200 h） | 第六B段第一天用 2 小时侦查 `scip.pxd`，据此重估 |

## 九、术语速查

| 词 | 意思 |
|---|---|
| `incumbent` | 当前已找到的最好可行解 |
| `best bound` / `dual bound` | 分支定界得到的、约束未知最优值的有效界 |
| `gap` | incumbent 与 bound 之间的差距 |
| `nPDI` | 本项目主指标：固定跨度归一化 gap 在 300 s 上的时间平均 |
| `baseline` | 拿来比较的方法 |
| `label` | 昂贵专家告诉模型"这个节点最好选哪个变量" |
| `checkpoint` | 训练后保存下来的模型文件 |
| `Pilot-A` | 训练**前**的七道硬门 |
| `Pilot-B` | 训练**后**、正式测试**前**的完整彩排 |
| `ID test` | 与训练条件同分布的测试 |
| `OOD test` | 故意改变规模 / 场景结构 / 回传条件的分布外测试 |
| `headroom` | 完美专家相对默认策略能压缩多少搜索树，即"有没有可赢的空间" |
| `shadow inference` | 真跑一遍 GNN 但忽略输出，纯粹为了测量调用开销 |
| `circuit breaker` | 出问题后对该实例关闭后续 GNN 调用的熔断机制 |
